# 2506.05334 Search Arena: Analyzing Search-Augmented LLMs

- 日期：2025-06（v2 為 2026-03）
- 發表狀態：同行評審（ICLR 2026）
- 作者類型：學術（UC Berkeley）
- 一句話總結：發布 24,069 段對話、12,652 個偏好票的大規模搜索增強 LLM 競技場數據，發現用戶偏好與引用數量正相關且對「不相關引用」不敏感，而在搜索場景中不用搜索的模型明顯落後。

## 研究問題
- 真實用戶向搜索增強 LLM 問什麼、偏好什麼樣的回答（長度、推理、引用數量、引用來源類型、引用是否支持主張）？搜索與非搜索模型在兩種場景下表現如何？（§1、§2、§3）

## 研究設計
- 系統類型：真實商業引擎（經供應商公共 API；作者註明 OpenAI 用的是 web search API，與 ChatGPT 產品搜索功能不同）＋眾包偏好數據（Chatbot Arena 的 Search 分頁）。
- 涉及的引擎和模型，以及測試日期：Perplexity（sonar、sonar-pro、sonar-reasoning 等）、Gemini（2.0/2.5 Flash、2.5 Pro，Google 搜索接地）、OpenAI（gpt-4o-search-preview、mini、高上下文與位置變體），共 12–13 個模型配置（表 A.1、§2）；2025-03-18 至 05-08 收集。
- 樣本：24,069 段對話、12,652 個配對偏好票、11,650 位用戶、136 國、約 70 種語言（英語 58.3%），22.4% 為多輪（§1、§2.1）。引用歸因分析僅約 800 個對話（每種意圖約 100 個）（§3.2）。跨場景實驗：Text Arena 544 場、Search Arena 315 場，使用 Gemini-2.5 Pro 帶／不帶搜索（§3.3）。
- 對照設計：跨場景對照（搜索 vs 非搜索）；Bradley-Terry 模型加入特徵差異作控制；作者聲明分析是相關性而非因果（§3）。
- 評估方式：人類偏好投票（由提問用戶本人投票）；專家與用戶一致率僅 68%（100 樣本、排除平局，隨機為 50%）（§3）；意圖由 GPT-4.1 標註（與人工 Cohen kappa 0.812，top-2，150 樣本）；引用歸因由 LLM 流水線判定（我讀到的正文中未見該流水線精度的人工驗證數字）。
- 證據等級：B（真實商業搜索增強模型、大規模真實用戶投票、多模型；但結果為偏好相關性而非真實行為，引用歸因樣本小且靠 LLM 判定）

## 主要發現（逐條列出，附數字和出處節號）
1. 真實用戶提問只有 19.3% 是事實查找，其餘為資訊綜合、分析、推薦、解釋等（圖 1、§2.2）。
2. 用戶偏好較長回答：βlength=0.334；事實查找類的長度係數 0.156，約為全體的 1/2.14（§3.1）。
3. 引用數量與偏好正相關：βcitations=0.209（§3.2）；模型分數與平均引用數的線性擬合為 score=17.192 x citations+939.23（圖 4）。推理模型引用較少（§3.2）。sonar-pro 高搜索上下文平均勝率 63.9% 對中等 57.6%（p<0.01）；GPT-4o 兩種上下文差異不顯著（§3.1）。
4. 引用來源類型：引用科技/程式平台（β=0.073）、社群平台（β=0.061）、社交媒體（β=0.057）與偏好正相關；引用 Wikipedia 為負（β=-0.071）（§3.2）。作者的解釋（內容冗長、不適合即時性查詢）來自對被拒絕回答的檢視，非因果檢驗。
5. 引用歸因：支持型引用 βsupport=0.29，不相關型引用 βirrelevant=0.27，皆與偏好正相關；矛盾型不顯著。用戶似乎不區分有據與無關的引用（§3.2、圖 6 右，約 800 段對話）。
6. 跨場景：Text Arena 中搜索與非搜索整體相當（搜索勝 26%、非搜索勝 28%、平局 45%；p=0.244），事實查找搜索勝出（p=0.012），資訊綜合 p=0.095，文字處理偏向非搜索（p=0.077）。Search Arena 中非搜索模型明顯落後（搜索勝 40%、非搜索勝 29%、平局 31%；p=0.009），事實查找 p=5.8x10^-5（§3.3）。
7. 引用格式隨機化後，格式對偏好與排名沒有顯著影響（附錄 A.2）。

## 對應原理和管線階段
- 原理編號：[1, 4, 6, 10]。1：搜索對參數知識的補充；搜索場景中不搜索明顯吃虧，一般聊天中搜索不損害；4：較大搜索上下文與偏好相關；6：用戶不區分支持與無關引用；10：用戶偏好的來源類型（社群/科技平台偏好、Wikipedia 負向）關聯內容生態。
- 管線階段：觸發 → 檢索 → 生成/引用 → 用戶行為。
- 新原理候選：「引用是說服信號」——用戶偏好與引用數量相關而對是否支持不敏感，引用數量可能成為可被操縱的表面特徵（僅為相關性，作者未測試操縱）。

## 對實踐的含義
- 有實驗支持的做法：（非優化研究）在搜索場景中，被偏好的回答傾向引用科技社群與社群平台，且引用數量較多（皆為相關性）。
- 作者建議但未經驗證的做法：改進來源過濾、優化何時觸發搜索、以客觀指標（事實性、引用—主張一致）補充人類偏好（§5）。
- 被證明無效或有害的做法：以用戶投票作為可信度標準有風險（用戶對不相關引用不敏感）。

## 局限與效度威脅
- 全部分析為相關性；用戶自願投票有人口偏差；用戶與專家一致率僅 68%（§3、§5）。
- 引用歸因分析僅約 800 段對話，由 LLM 流水線判定；意圖分類 kappa 0.812 只在 150 個英俄中樣本驗證。
- 使用 API 而非消費者產品；模型配置（搜索上下文大小等）與其他變數共線，難以分離獨立效應；未做重複測量。
- 跨場景實驗樣本較小（544、315）且只用一個模型（Gemini-2.5 Pro）。
- 用戶預期被「搜索模式」條件化，不必推廣到一般搜索用戶。

## 與其他研究的關係
- 支持哪些研究的結論：與 2304.09848 一致，引用可被感知為可信而不必真實支持；與 2410.22349 的用戶行為觀察（少量來源、信任引用外觀）相互印證。
- 與哪些研究的結論矛盾：一般聊天場景中搜索並無顯著整體優勢（p=0.244），與「搜索總是有益」的預期不同；其餘無直接矛盾。

## 值得到從業者社群（Reddit）驗證的問題
- 從業者是否觀察到 AI 搜索更偏向引用 Reddit、技術社群、YouTube，而較少引用 Wikipedia？
- 增加頁面上的外部引用/參考文獻，是否使其更容易被 AI 回答選中（用戶偏好只是相關性）？
