# 2510.11438 What Generative Search Engines Like and How to Optimize Web Content Cooperatively

- 日期：2025-10
- 發表狀態：預印本（標註 "Preprint: Work in Progress"）
- 作者類型：學術為主（CMU），第二作者隸屬 Vody，致謝稱研究獲 Vody 部分資助（商業關聯需留意）
- 一句話總結：AutoGEO 讓 LLM 比較高/低可見度文件對來自動歸納「引擎偏好規則」，再用規則指導改寫（AutoGEO_API）或作為 RL 獎勵訓練小模型（AutoGEO_Mini），在 3 個資料集與 3 個 LLM 引擎上提升可見度並聲稱不損害回答品質，但部分引擎/資料集的精確度下降。

## 研究問題
生成式引擎在使用檢索內容生成回答時有哪些可解釋的偏好？能否據此自動學習「合作式」GEO——提升可見度同時保持引擎回答的效用（GEU）？

## 研究設計
- 系統類型：可複現 RAG 管線（每查詢 5 篇候選文件，ClueWeb22 上的稠密檢索）
- 涉及的引擎和模型，以及測試日期：GE 由 gemini-2.5-flash-lite、gpt-4o-mini、claude-3-haiku-20240307 構成；教師模型 Gemini-2.5-pro；小模型 Qwen3-1.7B（§4）。未註明測試日期。
- 樣本：GEO-Bench（8,000 訓練/1,000 測試）；新建 E-commerce（來自 LMSYS-Chat-1M 篩選，1,667 訓練/416 測試）與 Researchy-GEO（Researchy Questions 前 10,000 訓練/1,000 測試）；只有 Researchy-GEO 有標準答案（§4）。
- 對照設計：Vanilla（無改寫）、GEO 論文的 9 種方法、兩種對抗方法（Hijack、Poisoning，來自 Nestaas 等）；消融（規則、RL 獎勵成分）；規則跨引擎/領域轉移；低可見度文件子集。
- 評估方式：GEO 指標為客觀（Word、Pos、Overall）；效用 GEU 沿用 DeepResearchGym：相關性（KPR、KPC）、忠實度（Precision、Recall）、品質（Clarity、Insight），其中部分為 LLM 評判。規則重疊的 Jaccard 由人工標註關鍵字計算（§5.3）。被優化的是單一目標文件還是全部文件，正文未詳述（僅見以 d̂ 取代 d）。
- 證據等級：D（可複現 RAG 管線＋多引擎；GEU 部分為 LLM 評判）。

## 主要發現（逐條列出，附數字和出處節號）
1. 表 1（Gemini 引擎）：AutoGEO_API Overall 在 E-commerce 34.05、GEO-Bench 34.92、Researchy-GEO 43.76；Vanilla 分別為 18.32、19.44、20.18；最強基線 Fluency Optimization 分別為 22.99、23.73、27.75。AutoGEO_Mini 為 25.25、27.12、38.53。作者稱 API 版比最強基線最高提升 50.99%、Mini 版平均提升 20.99%，並稱整體平均提升 35.99%（§1、§5.1）。
2. 跨引擎（表 2，Researchy-GEO Overall）：Vanilla 20.18/19.49/20.18 → AutoGEO_API 43.76（Gemini）/35.48（GPT）/30.51（Claude）；Mini 38.53/33.31/30.23。
3. 低可見度文件（表 3，Researchy-GEO，Gemini）：Vanilla Overall 9.46 → Fluency 16.78 → AutoGEO_API 35.83、Mini 30.24（§5.1）。
4. 效用整體大多維持：如 Gemini 上 Researchy-GEO 的 Precision 96.05→97.02（API）、Recall 99.22→99.17（表 2）。但表 2 也顯示下降：Claude 引擎 Researchy-GEO Precision 96.51→84.98（API）、84.88（Mini）；Claude 上 GEO-Bench Precision 83.45→78.78（API）；Claude 上 E-commerce Precision 53.45→51.24（Mini）；Mini 的 KPC（越低越好）在三個引擎上均高於 Vanilla（0.34 vs 0.27、0.34 vs 0.26、0.36 vs 0.31）。這些與作者「維持效用」的總結（§5.2）並不完全一致，作者未討論這些例外。
5. 對抗方法：Hijack/Poisoning 提升可見度（Overall 31.20/30.71，Vanilla 20.18），但 GEU 低於 Vanilla（如 Hijack Insight 49.52 vs 51.07；Poisoning Clarity 57.82 vs 60.10）；AutoGEO_API 為 43.76 且 GEU 不降（表 4）。
6. 偏好規則有跨引擎共性、跨領域差異：規則關鍵字 Jaccard 重疊 Gemini–GPT 78.95%、Gemini–Claude 84.21%、GPT–Claude 84.21%（圖 2a）；Researchy-GEO 與 GEO-Bench 88.24%，但與 E-commerce 僅 34.78% 與 40.00%（圖 2b）。通用規則例如「全面涵蓋」「深入解釋原因與機制」；電商偏「逐步指引/可操作建議」（表 5）。
7. 規則轉移：自身引擎/資料集的規則最好；轉移規則仍高於 Vanilla（≤20.18）（§5.3、圖 2c,d）。單條規則各自都有增益，完整規則集優於任一單條（圖 3、§5.4）。
8. AutoGEO_Mini 消融（表 6，Researchy-GEO Overall）：完整 38.53；去掉規則獎勵 31.41（影響最大）；去掉語義獎勵 37.79；去掉結果獎勵 34.38；去掉規則 prompt 37.04（§5.4）。成本約為 AutoGEO_API 的 0.0071 倍（§1、§3.2.2；細節在附錄）。

## 對應原理和管線階段
- 原理編號：[4, 5, 6, 9, 1]。5：規則多為內容結構/涵蓋度/可操作性；6：以 GEU 檢測改寫是否損害保真；9：對抗式 vs 合作式優化的效用取捨；1（弱）：不同 LLM 各有偏好規則，屬於模型內部偏好。
- 管線階段：重排/上下文、生成/引用、吸收/保真
- 新原理候選：「引擎偏好可學習且因模型與領域而異」——不同 LLM 與領域有各自偏好規則，可自動歸納取得（規則轉移實驗，需更多引擎驗證）。

## 對實踐的含義
- 有實驗支持的做法：讓內容更全面、深入（原因與機制）、電商內容提供逐步/可操作資訊（規則歸納結果，經改寫後在模擬 GE 中提升可見度）；使用引擎/領域專用規則優於通用規則（圖 2c,d）。
- 作者建議但未經驗證的做法：持續監測引擎偏好並自動更新規則；擴展到 agentic 與多模態（§6）。
- 被證明無效或有害的做法：Hijack/Poisoning 式對抗改寫雖提升可見度但降低效用（表 4）；關鍵字堆砌在 GEO-Bench 上低於 Vanilla（Overall 18.05 vs 19.44，表 1）。

## 局限與效度威脅
- 作者自述：本文為 "Work in Progress" 預印本；文中未見獨立的局限章節。
- 我方觀察：GE 為便宜模型（flash-lite、4o-mini、3-haiku），非商業搜尋引擎；文件從 ClueWeb22 稠密檢索，非真實搜尋；規則由 LLM 歸納、在同一 GE 上評估，有循環性；GEU 中 Clarity/Insight 為 LLM 評判；Claude 引擎上精確度下降未被討論；改寫由強模型完成，可能新增內容；GEO 指標為字數/位置，非用戶行為；無顯著性檢驗/信賴區間；「平均提升 35.99%」的計算方式正文未詳述。
