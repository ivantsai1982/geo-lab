# 2602.03608 Controlling Output Rankings in Generative Engines for LLM-based Search（CORE）

- 日期：2026-02
- 發表狀態：預印本（首頁標註 Preprint, February 4, 2026）
- 作者類型：學術（UIUC 等；未見商業服務商利益揭露）
- 一句話總結：在黑箱設定下，於「被檢索到的商品文本」後附加推理式或評論式文字，就能讓原本排在候選清單最後（第 10）的商品在 GPT-4o、Gemini-2.5、Claude-4、Grok-3 的輸出排名中大幅上升；同時證明基線排名幾乎完全跟隨檢索順序。

## 研究問題
LLM 搜索（生成式引擎）給出的推薦排名，多大程度上被上游檢索順序決定？在只能改動商品文字（標題、描述、評論）、無法動 LLM 與檢索器的黑箱條件下，能否把排在最後的商品推進 Top-k？（§1, §3.1）

## 研究設計
- 系統類型：固定上下文 LLM（Amazon 前 10 商品資料以 JSONL 餵給合成 LLM，並非實際商用 AI 搜索的完整管線）（§3.5, §4.1）；另含理論分析（§5 Discussion，附錄 C）
- 涉及的引擎和模型，以及測試日期：GPT-4o（gpt-4o-2024-11-20）、Gemini-2.5 Pro、Claude-4、Grok-3，均走官方 API 預設參數；影子模型 Llama-3.1-8B（另測 Vicuna-13B、Mistral-7B）。論文未給測試日期。（§4.1, §4.6）
- 樣本：ProductBench，15 個品類 × 每類 200 個商品，每商品取 Amazon 搜索介面的 top-10 推薦作為候選集（§3.5）。每品類的重複次數論文未明說；PSR 以 N 次 trial 計（§4.1）。
- 對照設計：基線＝原始排名；目標商品固定選候選清單最後一項（§4.1）。比較方法：STS、TAP、SRP、RAF，以 Llama-3.1-8B 生成內容再遷移到四個目標模型，僅在 Home & Kitchen（附錄 E 補另兩類）（§4.3）。
- 評估方式：客觀指標（Promotion Success Rate PSR@k、GPT-2 perplexity）；20 位標註者做流暢度與「是否被操縱」判斷（§4.4）
- 證據等級：E（固定上下文＋自建優化器，屬操縱／攻擊型評估，非真實引擎重複測量）

## 主要發現（附出處）
1. 基線 PSR 為 0%：目標為原清單最後一項時，LLM 輸出幾乎照檢索順序，末位項幾乎無機會進 Top-k（§4.2, Table 1）。作者由此主張「排名強烈受上游檢索限制」，但這是在固定候選、最差位置的設定下得出。
2. 推理式與評論式內容效果最大：兩者一般 Top-3 PSR 高於 85%，Top-1 接近或高於 80%（§4.2）。摘要給出四模型、15 品類最佳策略平均 91.4%@Top-5、86.6%@Top-3、80.3%@Top-1（Abstract）。
3. 字串式（亂碼式 token 優化，20 個 "!" 初始化）較弱：Home & Kitchen 上 GPT-4o 為 55.0%/45.5%/33.0%（Top-5/3/1），推理式 92.0/87.0/81.0，評論式 89.5/85.0/79.0（Table 1/2）。
4. 模型偏好不同：GPT-4o、Claude-4 更吃推理式；Gemini-2.5、Grok-3 更吃評論式（Gemini 評論式 94.5/89.5/83.5 對推理式 88.5/84.0/77.5，Table 2）；Claude-4 整體最高、Grok-3 反應較弱（§4.2）。
5. 優於既有方法：Home & Kitchen 上 GPT-4o Top-1，RAF 44.0%、SRP 42.0%、TAP 34.0%、STS 32.5%，對比 CORE-推理 81.0%（Table 2）。這些對手是在 Llama-3.1-8B 上產生後遷移，公平性受此設定影響。
6. 流暢度與可偵測性：perplexity 基線約 30，字串式約 1,500，推理式約 68–75，評論式約 31–33（Table 3）。人工：字串流暢度 1.2、偵測率 98.5%；推理 3.7、62.1%；評論 4.6、18.4%；基線 4.7、12.0%（Table 4）。
7. 位置敏感：在 top-3 候選各附一種策略並排列組合，評論式排第一時多數模型讓目標拿到第一名的比例超過 70%，推理式排第一時超過 65%，字串式在 70% 以上案例落第 3（§4.5, Table 5）。
8. 生成器／優化器與目標模型對齊時效果最好，優化器不匹配掉得比生成器不匹配更多；評論式跨模型遷移較穩（§4.6, Table 6）。影子模型換 Vicuna-13B、Mistral-7B 結果接近，Llama-3.1-8B 最好（Table 7）。
9. 防禦（附錄 J, Table 14，Home & Kitchen）：perplexity 過濾（閾值 50）幾乎去除所有字串內容，並使推理式降超過 75%，多數評論式保留；模式過濾和長度限制（4000 詞）使推理與評論成功率明顯下降。作者結論是三種防禦都「不足」（§5, 附錄 J）。
10. 理論（作者的形式化，非實驗）：log P[rank=1] = f(內容, q) − λk + c，即存在位置偏差 λ；作者宣稱在平滑假設下 PSR@1 可在有限步內達標（§5, 附錄 C）。

## 對應原理和管線階段
- 原理編號：[4, 9, 6]。4：檢索位置（相關性與位置）主導排名；9：優化與操縱走同一通道、防禦不足；6：評論式偽裝內容影響排名而不必然可信。
- 管線階段：重排/上下文、生成/引用
- 新原理候選：「生成式引擎的排名是對檢索順序的『保守重排』，位置偏差可被內容中的推理／評論式敘事覆寫」——可併入原理 4 與 9，論文未直接證明真實商用引擎有同樣行為。

## 對實踐的含義
- 有實驗支持的做法：在固定上下文實驗中，商品描述附上「比較式推理」或「像真實購買評論的敘事」可大幅提升被排前列的機率（Table 1/2）。但這是操縱性質，且本身就是被當作攻擊研究的。
- 作者建議但未經驗證的做法：提出 CORE 也可讓小商家提升可見度（Impact Statement）；防禦方向僅為「需更穩健機制」。
- 被證明無效或有害的做法：無意義字串式內容效果弱且被人與 perplexity 一眼識破（Table 3/4）；對防禦方，簡單過濾大多不足（Table 14）。

## 局限與效度威脅
- 並非真實商用搜索管線：候選集由作者爬取 Amazon 後直接餵入 LLM，未經真實檢索與排序，引擎內部檢索排序未涉及。
- 目標永遠是最後一項，且 PSR 以基線 0% 為對照，對「一般商品」的效應無說明。
- 對手方法用 Llama-3.1-8B 遷移，可能不利於對手；各表無信賴區間或重複次數。
- 評論式內容是偽造購買經驗，實際部署時可能被平台審核，論文未評估平台端信任信號。
- 人工評估只有 20 位標註者，每人五個樣本。
- 未記錄測試日期；模型皆是 API 而非其搜索產品。

## 與其他研究的關係
- 支持哪些研究的結論：支持「LLM 排名有位置偏差、可被注入內容操縱」的提示注入／排名操縱研究（文中引 Pfrommer 2024 等 TAP、Nestaas 2024）。
- 與哪些研究的結論矛盾：未見直接矛盾；與 GEO（Aggarwal 2024）的差別在於本文針對合成階段而非網站設計。

## 值得到從業者社群（Reddit）驗證的問題
- 在真實 ChatGPT／Perplexity 購物推薦中，評論式或推理式的商品描述是否真的改變排名？平台是否已過濾？
- 商品頁埋入「比較式敘述」是否被視為操縱、有無被降權的案例？
