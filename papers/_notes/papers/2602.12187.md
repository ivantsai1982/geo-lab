# 2602.12187 SAGEO Arena: A Realistic Environment for Evaluating Search-Augmented Generative Engine Optimization

- 日期：2026-02（v2 為 2026-08；KDD 2026 版本）
- 發表狀態：同行評審（KDD 2026, Jeju）
- 作者類型：學術（延世大學、建國大學）
- 一句話總結：用可複現的完整 RAG 管線（BM25 → cross-encoder 重排 → GPT-5-mini 生成）與 17 萬份帶結構欄位的網頁語料，發現只優化正文的 GEO 策略在檢索與重排階段普遍讓文件「掉隊」，生成階段增益也很小；優化 title／meta／heading／schema 等結構欄位可緩解，並提出分階段（stage-aware）優化。

## 研究問題
現有 GEO 基準（GEO-Bench、AutoGEO、C-SEO Bench、CC-GSEO-Bench）都在固定候選文件上只測生成階段，且丟棄結構資訊。優化後的文件還能否被檢索、重排進上下文？結構資訊（title、meta description、headings、schema/JSON-LD）在整個管線中扮演什麼角色？（§1, Table 1）

## 研究設計
- 系統類型：可複現 RAG 管線（自建）；語料來自 Google Custom Search API 抓取的真實網頁
- 涉及的引擎和模型，以及測試日期：預設 BM25（檢索）、Qwen3-Reranker-4B（重排）、GPT-5-mini（生成）；替換測試：Dense（BGE-base-en-v1.5）與 Hybrid 檢索、BGE-Reranker-v2-m3、Claude Sonnet（文中寫 Claude-Sonnet-4.6）作生成器；優化改寫模型 GPT-5-mini、LLaMA-3.3-70B、Qwen3-80B（§4, §5.2, §5.4）。測試日期未給。
- 樣本：9 個 IR 資料集各抽 300 query，共 2,700 query；每 query 最多 100 個搜索結果，過濾後 171,003 份唯一文件，平均每 query 63 份候選（§3.1）。每個 query 隨機選一個進入生成階段（重排 top-10）的文件作為目標（§3.4）。
- 對照設計：基線為未優化的同一文件；優化後重新索引並用同一 query 重跑管線，比較 Hit Rate 與 ΔRank；分三種範圍：只改正文、只改結構欄位、兩者皆改（§3.4, §5.1）。10 種策略：GEO 論文的 8 種（Authoritative、Cite Sources、Easy Language、Fluency、Quotation、Statistics、Technical Terms、Unique Words）＋All-in-One＋AutoGEO（§4）。
- 評估方式：客觀指標（檢索 H@20、重排 H@10、生成引用率 Citation Rate、ΔRank）；生成階段引用歸因用 fuzzy matching 找被引用句的來源區域（§5.2）。無 LLM 評判主結論。
- 證據等級：D（可複現完整 RAG 管線，但為自建管線而非商業引擎；BM25 檢索是簡化選擇）

## 主要發現（附出處）
1. 只優化正文，全階段平均下降：檢索 H@20 由 0.58 降至 0.53（−9%），重排 H@10 由 1.00 降至 0.84（−16%），生成引用率由 0.50 降至 0.47（−6%）（Table 2 左，Avg 列）。
2. 「技術術語」與「獨特用詞」等改詞策略檢索損失最大（Tech. −14%、ΔRank −6.23；Unique −8%），作者歸因於與 query 的詞彙不匹配（BM25）；AutoGEO 最差，檢索 H@20 0.37（−36%）、ΔRank −22.35，作者歸因於大幅擴寫稀釋關鍵詞（§5.1, Table 2）。
3. 只優化結構欄位：檢索 H@20 平均 0.71（+22%）、ΔRank +2.72；引用率平均 0.52（+2%），但重排 H@10 仍降至 0.83（−17%）（Table 2 中，Avg）。
4. 兩者皆改比只改結構欄位增益更小：檢索 +15%、ΔRank −0.56，重排 H@10 0.75（−25%）（Table 2 右，Avg）。作者推測是正文修改的負面檢索效應抵消結構增益（§5.1，屬解釋而非獨立驗證）。
5. 重排是「持續瓶頸」：所有策略在所有範圍下重排均劣化；5.8% 目標文件從第 10 名掉到第 11 名而被生成器排除（§5.1）。個案研究（Figure 3）顯示：加入直接回應 query 資訊需求的內容會升，擴大範圍會降；答案放在前段升、被推到後段降。
6. 生成階段的引用主要來自正文，結構欄位被引用較少（Figure 5, §5.2）；結構欄位主要助「浮現」（檢索），正文助生成引用。
7. 領域差異：一般資訊型（Web Search、General QA）最受益；Shopping 是唯一所有優化方法都降低引用率的領域（Figure 4, §5.2）。
8. 骨幹模型：LLaMA-3.3-70B 產出短而關鍵詞密集（平均 296 詞，GPT 為 782 詞）文件，檢索勝率 42.2% 高於 GPT-5-mini 的 38.0%；重排階段 GPT-5-mini 勝率 63.1%（LLaMA 13.0%），生成階段 73.2%（LLaMA 7.0%）（§5.2, Figure 6）。
9. 策略組合：EasyLang+Quote 等組合提高生成表現但檢索 ΔRank 仍為負；作者提出的 StageAware 在「兩者皆改」設定下檢索 H@20 0.75（+28%）、ΔRank +4.86，重排 H@10 0.80，引用率 0.58（+1.01 ΔRank）（Table 3）。這是作者自己的方法對比自己設定的基線，需保留。
10. 穩健性：換 Dense／Hybrid 檢索、BGE 重排器、Claude Sonnet 作生成器，只改正文仍不可靠或劣化（Table 4：Dense 平均 −2%、Hybrid −5%；Table 5：BGE 重排平均 −19%，Claude 生成基線引用 0.77、平均 −12%）（§5.4）。

## 對應原理和管線階段
- 原理編號：[3, 4, 5, 6]。3：語義／詞彙匹配決定召回；4：進入上下文的相關性與位置（答案前置、主題一致）；5：可抽取證據與結構；6：被檢索到不等於被引用。
- 管線階段：抓取/索引、檢索、重排/上下文、生成/引用
- 新原理候選：「各階段獎勵的文件特徵不同」（檢索偏關鍵詞與結構欄位，重排偏主題契合與答案前置，生成偏含具體證據的正文），即分階段優化；可歸入原理 3–5 的交叉說明。

## 對實踐的含義
- 有實驗支持的做法（在此模擬管線中）：在 title／meta description／headings／schema 中補充核心實體、數字與詞彙以提高檢索命中（Table 2 中）；答案前置並保持主題一致以利重排（Figure 3 個案）。
- 作者建議但未經驗證的做法：四條 stage-aware 準則（§5.3）中僅 StageAware 作為整體方法在 Table 3 測過，各準則獨立貢獻未做消融；領域適配僅為建議。
- 被證明無效或有害的做法：以生僻／技術術語改寫、大幅擴寫（AutoGEO 式）會降低詞彙檢索與重排（Table 2 左）；在 Shopping 領域所有策略都降低引用率（Figure 4）。

## 局限與效度威脅
- 基線目標文件都是「已進入 top-10 的文件」，H@10 基線 = 1.00（Table 2 註），因此重排階段只可能下降；此設計使「重排劣化」的解讀應相對於已在頂部的文件，不能推廣到低排名文件（此為我方對設計的觀察）。
- 管線用 BM25＋單一 cross-encoder，商業引擎未必如此；詞彙不匹配導致的檢索劣化在 BM25 上最顯著（Dense 較小，Table 4）。
- 優化不知道 query（無 query 條件），與真實網站所有者相同，但不排除實際更佳做法。
- 結構欄位優化是直接改寫索引欄位，真實世界中 meta/schema 是否被引擎採用未直接驗證（作者引用他人證據，§2.3）。
- 生成階段引用率增減多在 ±0.05 以內，未見顯著性檢驗；生成器僅 GPT-5-mini 與 Claude Sonnet。
- 未註明測試日期；靜態語料快照。

## 值得到從業者社群（Reddit）驗證的問題
