# 2603.09296 Diagnosing and Repairing Citation Failures in Generative Engine Optimization（AgentGEO / MIMIQ）

- 日期：2026-03
- 發表狀態：預印本（首頁標註 Preprint, March 11, 2026）
- 作者類型：學術（Virginia Tech、浙江大學）
- 一句話總結：把 GEO 目標從「貢獻度」改為二元的「是否被引用」，用 949 組「未被引用 vs 被引用競爭者」對比建立引用失敗分類，並提出逐頁診斷再針對性修復的 AgentGEO；在模擬引擎上引用率由 56.58% 提升到 79.52%，同時只改約 5% 內容。

## 研究問題
現有 GEO 用 Word Count 等貢獻度指標並統一套用改寫規則，無法回答「這個頁面為何根本沒被引用」。能否診斷失敗成因並做針對性修復，且泛化到未見過的 query？（§1）

## 研究設計
- 系統類型：可複現 RAG 管線（作者自建的「GE 模擬」：標準檢索與生成元件加明確引用指令；作者說明商用管線不公開，故用模擬）（§6.1）
- 涉及的引擎和模型，以及測試日期：生成器 gpt-4.1-mini 與 claude-haiku-4-5-20251001；兩種引用方式：in-context 生成、attribute-first-then-generate（§6.1–6.2）。未給日期。
- 樣本：分類學：GEO-Bench 10 個領域，949 組對比配對（§3.2）。MIMIQ：從 ClueWeb22 等取 204 個網頁，每頁 60 個 LLM 生成的 query（20 訓練＋40 測試），共 12,240 query；OOD 與 HTML 變體各 50 頁（§5.2, 附錄 A）。GPT vs Claude 比較僅用 50 頁子集（§6.2）。
- 對照設計：Vanilla；GEO-Bench 的 8 種規則（另含 Keyword Stuffing）；AutoGEO；訓練 query 上優化、留出 query 上評估（§5, §6.1）。
- 評估方式：客觀指標（引用率 CR；Word/Pos/Wordpos 貢獻度；DeepResearchGym 的 Precision/Recall/Clarity/Insight 為 LLM 評判，是否人工驗證未見；忠實度 TF-IDF/Embedding/Jaccard 相似度）（§6.1）。失敗分類由 LLM 診斷（提示詞在附錄 E），未見人工驗證說明。query 亦由 LLM 生成並經驗證模型過濾（§5.1）。
- 證據等級：D（可複現 RAG 管線；但診斷、query 生成與部分評估依賴 LLM）

## 主要發現（附出處）
1. 基線約 43% 的主題相關網頁在基線條件下完全不被引用（§1）。
2. 失敗分佈（949 對，Figure 2）：語義對齊 62.2%、內容品質 27.1%、技術完整性 10.1%（抓取／解析）、系統性排除 0.6%（競爭冗餘、視窗截斷）。細項圖中最大幾項為 29.1%、32.3%、26.1%（標籤與數字的對應在文字抽取中不清，需查原圖）。
3. AgentGEO 主結果（GPT，Table 2）：in-context 生成 CR 79.52%（Vanilla 56.58%，AutoGEO 68.80%，最佳 GEO-Bench 規則 Easy-to-Understand 71.11%）；attribute-first 設定 70.00%（Vanilla 60.20%，AutoGEO 65.97%）。作者稱相對提升超過 40%（79.52/56.58≈+40.5%）（Abstract, §6.2）。
4. 只改約 5% 內容，基線方法平均改約 25%（Abstract, §1）；忠實度：TF-IDF 94.23、Embedding 93.20、Jaccard 82.40，對比 AutoGEO 67.49/76.99/17.97（Table 2）。
5. 跨引擎：Claude（haiku-4.5）上 CR 42.40 → AutoGEO 46.80 → AgentGEO 54.80；GPT 為 56.58/68.80/79.52；效用指標與 Vanilla 相近（Table 3, 50 頁子集）。
6. 泛化：MIMIQ-OOD 上 AgentGEO 70.62%，比 AutoGEO 高 6.44%；AutoGEO 平均縮短頁面長度 43%（附錄 B）。MIMIQ-HTML 上 67.19%。跨方法遷移：優化用 attribute-first 回饋、評估用 in-context，CR 由 69.98% 升至 84.29%（附錄 B.1, Table 5）。
7. 通用規則可能傷害長尾內容：健康類基線引用率已約 80%，AgentGEO 反而為負或極小提升，AutoGEO 在多個主題低於 Vanilla（§6.3, Figure 4）。作者解釋（部分優化步驟刪除了領域特定資訊）屬事後觀察。
8. 並非所有失敗都能修復：50 頁優化後訓練 query 引用率由 57.0% 升至 83.7%，但仍有 163 個 query 未被引用；個例（大學 ML 課程頁輸給 Coursera、edX）顯示引擎可能偏向網域層級權威（§6.4）；作者說這是推測性邊界。
9. 訓練 query 數量影響：平均 CR 從 0 個時 0.6837 升至 80 個時 0.8044（Table 7）；批次大小 5 最佳；記憶機制優於隨機選工具（附錄 B.4）。

## 對應原理和管線階段
- 原理編號：[5, 6, 3, 9]。5：可抽取證據、結構與答案位置；6：引用與否是二元事件，且與「貢獻度」不同；3：抓取／解析失敗與權威來源冗餘；9：公共規則可能傷害長尾（零和與偏向強者）。
- 管線階段：抓取/索引、檢索、重排/上下文、生成/引用
- 新原理候選：「引用失敗是異質的（不同管線階段，各需不同修復）」，可作為原理 6 的診斷框架；「網域權威在內容修改之外的固定劣勢」與原理 3、9 相關。

## 對實踐的含義
- 有實驗支持的做法（模擬引擎中）：針對性小幅修改（HTML 修復、內容重排、補實體、提高資訊密度）優於整頁通用改寫；引用率與被改動比例並非正相關（Table 2, Abstract）。
- 作者建議但未經驗證的做法：對商用引擎驗證留待未來工作（§7）；分類學中的抓取失敗（JS 渲染、存取封鎖）在實驗中主要透過 MIMIQ-HTML 間接測試。
- 被證明無效或有害的做法：通用規則（如 Technical Terms 55.84% 低於 Vanilla 56.58%）不穩定；AutoGEO 壓縮頁面約 43%（OOD）導致資訊流失；某些主題套用通用規則使引用率下降（§6.3）。

## 局限與效度威脅
- 引擎是自建模擬，作者在結論明說尚待對商用引擎驗證。
- 測試 query 由 LLM 合成而非真實用戶，且 query 由網頁內容生成（「保證可由該頁回答」），這使引用機率高於真實情境，43% 未被引用的數字需在此背景下解讀。
- 診斷與修復都由 LLM 完成，分類學比例未見人工評分者一致性。
- Table 2 的 Word 類貢獻度在 attribute-first 下 AgentGEO 的 Pos、Wordpos 低於 AutoGEO（31.57 vs 34.33 等），提升並非全面。
- Claude 子集僅 50 頁；無顯著性或多次重跑（除訓練集大小表的標準差外）。

## 與其他研究的關係
- 支持哪些研究的結論：支持「通用改寫規則不穩定」的觀察（與 2602.12187 中 AutoGEO 傷害檢索的結果方向一致）；與 GEO-Bench 的貢獻度指標相比，強調引用二元性。
- 與哪些研究的結論矛盾：對 AutoGEO 的表現評價與其原論文相反（此處 AutoGEO 在部分主題低於 Vanilla）；對 GEO-Bench（Aggarwal 2024）中各規則的增益也給出較小且不一致的結果（如 Technical Terms 低於 Vanilla）。

## 值得到從業者社群（Reddit）驗證的問題
- 網頁「被 AI 引用失敗」的常見原因在真實場景中是 JS 渲染／爬蟲封鎖，還是內容與 query 不對齊？
- 權威網域（Coursera、Wikipedia）是否真的在內容相近時穩定壓過小站？
