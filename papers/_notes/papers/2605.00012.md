# 2605.00012 Exploring LLM biases to manipulate AI search overview

- 日期：2026-03
- 發表狀態：預印本（未註明；arXiv cs.IR）
- 作者類型：業界（單一作者，E-AI.Solutions，AI 諮詢/服務公司；非明顯的 GEO 服務商，但為商業實體）
- 一句話總結：用 RL（Dr.GRPO）訓練 1B 小模型改寫搜索結果 snippet，使其更容易被 LLM Overview 選中；發現偏好是「相對而非絕對」的，並展示在參考 snippet 中投毒可污染改寫輸出（有限的概念驗證）。

## 研究問題
LLM Overview（用 LLM 從搜索結果選來源並生成摘要）是否存在穩定偏好？這些偏好能否被小模型透過 RL 學到並用於操縱選擇？攻擊是否可行？（摘要、§1）

## 研究設計
- 系統類型：模擬的 LLM Overview（簡化版）：輸入 query + 7–10 條搜索結果（URL、標題、snippet），要求 LLM 回傳 3 個最相關來源的 ID（§6.1、附錄 A）。屬固定上下文 LLM，搜索結果來自真實搜索引擎，但 Overview 為自建。
- 涉及的引擎和模型，以及測試日期：Overview 用 gpt-4.1-nano（主要）、gpt-4.1-mini、gpt-5-nano、gpt-5-mini；改寫策略模型為 gemma-3-1b-it（LoRA，Dr.GRPO，無 KL）（§6.3、§8）；日期約 2026-03（引用日期 2026-03-15/20）
- 樣本：Amazon ESCI 商品查詢約 3000 條用於訓練；偏差檢測手工整理 90 個樣本；測試集 90 個新樣本，每樣本 1 個目標 snippet（§4、§5、§6.5）
- 對照設計：偏差檢測用 7 個擾動實驗（溫度、順序打亂、URL 打亂、輕/重改 prompt、換模型）；改寫評估為改寫前後的被引用比例（§5、§6.5）
- 評估方式：客觀指標（目標 snippet 是否被選中）；無 LLM 評判
- 證據等級：E（固定上下文、合成 Overview、小樣本 90）

## 主要發現（逐條列出，附數字和出處節號）
1. 偏差存在：在 90 個樣本、每個 7 次擾動實驗中，48 例中同一 snippet 在全部 7 次實驗都被選中，30 例中有 2 個以上 snippet 在 7 次中一次也沒被選（§5）。零假設（每條被選概率 3/N）下，被選 0 次或 >6 次的概率各約 2%。作者認為這是偏差證據；但（作者也承認）若確有 3 條高質量結果，此現象亦可預期，因此他用「所有結果都相關」的人工論據排除（表 1 僅一個例子 "starbucks gift cards 10"）。
2. 「earned media bias」的示例：在該例中 Best Buy、Amazon 為 7/7，品牌官網 Starbucks 為 2/7，Walmart 為 0/7（表 1）——僅單一示例，不是統計證據。
3. 改寫策略：無條件改寫失敗（§6.2）；讓改寫器看到其他競爭 snippet（條件式改寫）才有效，作者據此推斷「Overview 的偏好是相對而非絕對」（§6.4）——這是作者對訓練現象的解讀，非直接檢驗。
4. 長度作弊：去掉長度約束後，策略傾向把 snippet 寫得更長，說明 Overview 有長度偏好（§6.4）；最佳獎勵為長度獎勵權重 0.2 + Overview 獎勵（§6.4）。
5. 測試結果：訓練後策略在 90 個新樣本上提高被選中比例，結果只在圖 4 給出，正文沒有具體百分比——無法引用數字。
6. 模型差異：訓練對 gpt-4.1-nano、gpt-4.1-mini、gpt-5-nano 有效，對 gpt-5-mini 無效（獎勵不增長）；作者發現 gpt-5-mini 對 URL 有強偏好（圖 5–7），「假設」是偏差所致（§8、§9）。
7. 攻擊（概念驗證，非廣泛實驗）：目標 snippet 攻擊失敗（策略忽略毒化文字）；標題攻擊失敗（標題被注意）；參考攻擊成功（毒化參考 snippet 後，改寫出的目標 snippet 含毒化資訊並被引用，例：query "casio watch bands replacement men"）（§7）。作者自承實驗「不夠廣泛」，僅一例。

## 對應原理和管線階段
- 原理編號：[4, 5, 9]。4：進入上下文後的選擇偏好（長度、來源類型、URL）；5：snippet 的可抽取內容；9：優化與操縱走同一條通道（RL 改寫與投毒共用同一機制）。
- 管線階段：重排/上下文、生成/引用
- 新原理候選：「選擇是比較性的：贏得引用取決於相對於同一候選集中其他來源的優勢」——可補充到原理 4（相關性和位置）。

## 對實踐的含義
- 有實驗支持的做法：在條件式（看得到競爭 snippet）的設置下，小模型 RL 改寫可提高被選中概率（僅在其 gpt-4.1 系列模擬 Overview 內；量化見圖 4，正文無數字）。
- 作者建議但未經驗證的做法：無明確站點建議；提出需要進一步研究特定模型偏差。
- 被證明無效或有害的做法：無條件改寫（失敗）；單純延長 snippet 雖然有效但為 reward hacking，在真實搜索引擎有長度限制下不可用。

## 局限與效度威脅
- 簡化的 Overview（只回傳 3 個 ID，不生成摘要）；假設與真實 Overview 結果強相關，僅有「初步實驗」佐證（§6.1）。
- Overview 只看 URL+標題+snippet；真實系統會讀頁面全文。
- 測試 90 個樣本；主要 Overview 模型為 nano 級；圖 4 數字未進正文；攻擊只有一兩個例子。
- 作者自述：可能的失敗原因包括 RL 算法限制、探索不足、LoRA、需超越初始分佈等（§9）。
- 偏差檢測的實驗設計本身無法區分「偏差」與「質量差異」。

## 與其他研究的關係
- 支持哪些研究的結論：Chen 等（earned media bias，[3]）；Nestaas 等的 Preference Manipulation Attacks；AutoGEO（Wu 等）與 Rewrite-to-Rank 的「LLM 改寫優化」方向。
- 與哪些研究的結論矛盾：與 AutoGEO 初期設置的結果不同：作者在短 snippet 上無條件改寫失敗（§6.2），而 AutoGEO 在較長文本上成功——是設置差異而非直接矛盾。

## 值得到從業者社群（Reddit）驗證的問題
- 搜索結果 snippet/meta description 的寫法（強調與同類競爭者的差異、含具體規格）是否影響 AI Overview 的引用？
- 電商站點被轉售商/聚合站壓過（earned media 偏好）的現象是否常見？
