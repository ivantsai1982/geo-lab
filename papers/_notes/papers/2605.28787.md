# 2605.28787 Do Data Agents Need Semantic Metadata? A Comparative Study in Agentic Data Retrieval

- 日期：2026-05（v2 為 2026-07-21）
- 發表狀態：預印本（arXiv cs.IR，未註明會議/期刊）
- 作者類型：業界（Google；作者曾建立 Google Dataset Search，被比較的兩個系統都是 Google 自家產品，存在潛在利益關係，論文未專門聲明）
- 一句話總結：在 58 條資料集搜索關鍵詞上，用同一 Gemini 2.5 Pro Agent 分別查 Google 網頁搜索（無結構化）與 Google Dataset Search（schema.org 語料，9,000 萬條）：語義 Agent 取回的頁面更常是可直接下載的登記頁，但能回答的問題少約 30%（40 對 56）。

## 研究問題
在 Agent 時代，網站是否仍需要 schema.org 等語義元數據，讓 Agent 找到「可執行的」資料集，還是 LLM 直接在非結構化網頁上就夠？（Sec.1）

## 研究設計
- 系統類型：真實商業引擎（Google Search 對 Google Dataset Search 兩個活索引），Agent 為自建（ADK + Gemini 2.5 Pro，溫度 0，僅用搜索工具，最多回傳 3 個資料集）
- 涉及的引擎和模型，以及測試日期：Google Search、Google Dataset Search；Gemini 2.5 Pro 同時作為 Agent 與評判；測試日期未寫明（ADK 參考註明 2026-04-22 存取）。
- 樣本：NTCIR-16 Data Search 的 IR 子任務中 58 條英文關鍵詞查詢（如 "air quality baltimore"）；基線 Agent 回答 56 題、取回 164 個資料集；語義 Agent 回答 40 題、取回 112 個（Sec.5）。單次運行，無重複次數說明。
- 對照設計：兩個近乎對稱的 Agent，變量是目標索引與語料。基線 Agent 會自動附加 "dataset" 等關鍵詞；語義 Agent 只用核心關鍵詞。Dataset Search 語料已用分類器濾掉約 80% 標註無效或誤用的頁面（Sec.3.1）。
- 評估方式：LLM 評判（Gemini 2.5 Pro，附思維鏈與證據引用）+ 人工驗證：兩位作者標註 11% 樣本，評判與人工的加權 Kappa 分別為 0.73（頁面類型）、0.78（可訪問性）、0.74（相關性）；約 31% 檢索（基線 29%，語義 33%）因爬取失敗轉人工標註（Sec.4.3）。
- 證據等級：C（商業系統，但評判所見頁面是抓取快照；Agent 為自建，不是真實用戶行為；不過檢索是真實活索引，介於 C 與 D，按主要結論取 C）

## 主要發現（逐條列出，附數字和出處節號）
1. 相關性無差異：「高度相關」比例基線 60.4%（99 個）、語義 60.7%（68 個）（Sec.5.1）。
2. 可訪問性：返回機器可讀資料頁的比例語義 71.4%，基線 48.7%；作者稱為 46.6% 相對提升（Sec.5.2）。
3. 頁面類型：DATA_REGISTRY 佔比語義 88.4%，基線 61.0%（相對提升 44.9%）；語義 Agent 的 DATA_NARRATIVE 相對減少 86.6%、DATA_EXPLORER 減少 55.7%、DISCOVERY_PORTAL 減少 100%（Sec.5.3）。摘要提到基線有 20.1% 為敘述性頁面、8.5% 為入口頁（該數字來自摘要，正文未再列）。
4. 嚴格 FAIR 標準（相關性 2 + 機器可讀 + 登記頁）的資料集級精度：基線 28.0%（46/164），語義 46.4%（52/112），p<0.01，相對提升 65.7%（Sec.5.4）。
5. 覆蓋度：基線 Agent 回答 56 題，語義 Agent 40 題（摘要稱基線多回答 40%）；作者把原因歸於 schema.org 標記採用有限，長尾領域尤甚（Sec.6.1，此為作者解釋，未做測試）。
6. 每個已回答查詢的結果密度：語義 1.30（52/40），基線 0.82（46/56）；差異不顯著（p>0.05）（Sec.5.4）。
7. 作者提出混合方案：先查語義層，空結果再退回非結構化搜索（Sec.6.4）；沒有實驗。

## 對應原理和管線階段
- 原理編號：[5, 8, 3]。5：結構化元數據讓可抽取證據更精確；8：Agent 依賴機器可讀、可直接執行的頁面；3：能否被特定垂直索引收錄取決於是否有標記（收錄門檻）。
- 管線階段：抓取/索引、檢索、生成/引用（Agent 選取的頁面類型）
- 新原理候選：「Agent 場景下的最後一公里可用性」：被找到不等於可執行；重要的是頁面是否提供機器可讀的資料載荷。這與「被引用不等於被使用」類似，但針對 Agent 的操作。適用範圍是資料集檢索，未證明適用於品牌/購物 GEO。

## 對實踐的含義
- 有實驗支持的做法：（僅資料集場景）發佈 schema.org/Dataset 標記並被 Dataset Search 收錄，可提高 Agent 取回的頁面是登記頁與機器可讀的比例（Table/Sec.5.2–5.4）。
- 作者建議但未經驗證的做法：多面向自然語言查詢可直接轉成含 license、dataType 等過濾條件的工具呼叫（Sec.6.3）；受限資料採人機接力；混合架構。
- 被證明無效或有害的做法：無直接證明。結構化語料以覆蓋度為代價（回答題數少），且不能證明 schema.org 本身是原因，因為語義語料同時改變了索引、排序與收錄機制。

## 局限與效度威脅
- 系統對比混淆了多個變量：語料（9,000 萬對數十億）、排序機制、分類器濾除 80% 標記、查詢擴展方式；作者自述不區分內部排序影響（Sec.7）。
- 「FAIR 合規」與「可執行」由 LLM 評判與頁面類型規則定義，且評判與 Agent 同為 Gemini 2.5 Pro；人工驗證僅 11% 樣本，Kappa 0.73–0.78。
- 31% 的頁面因爬取失敗轉人工，且此比例基線與語義相近，但人工標註者為論文作者，無盲評。
- 只有 58 條英文關鍵詞、單次運行；語義 Agent 只回答 40 題，樣本不對等；精度以檢索到的 URL 為分母，兩者分母不同。
- 領域是學術/開放資料集，不是商業或品牌查詢，不能直接推到一般 GEO。
- 未評估答案品質，只評檢索到的頁面。

## 與其他研究的關係
- 支持哪些研究的結論：與「結構化、可抽取內容提升 AI 使用」的方向一致；與 2511.18354 的「AI 原生語義接口」主張同向（後者只是願景）。
- 與哪些研究的結論矛盾：未直接引用或反駁其他 GEO 論文。它與「LLM 直接讀非結構化網頁已足夠」的預設對立，但結論僅限資料集發現任務。
