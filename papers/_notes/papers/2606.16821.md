# 2606.16821 How Much Can We Trust LLM Search Agents? Measuring Endorsement Vulnerability to Web Content Manipulation

- 日期：2026-06
- 發表狀態：預印本（未註明；arXiv cs.CL v2，2026-06-23）
- 作者類型：學術（KAUST、吉林大學、浙江大學、IDSIA）
- 一句話總結：SearchGEO 框架在受控代理中向真實快取搜尋結果注入五類操縱內容，測 13 個 LLM 後端：整體攻擊成功率從 Claude-Sonnet-4.6 的 0.0% 到 Gemini-3-Flash 的 31.4%；「多個不同來源互相佐證」是主要驅動因素，重複同一來源或改變排名位置無明顯影響。

## 研究問題
當 LLM 搜尋代理把開放網頁內容綜合為推薦時，攻擊者發布的頁面何時會被轉化為代理「背書」的主張（endorsement corruption）？哪類攻擊、哪些後端、哪些部署配置最脆弱？

## 研究設計
- 系統類型：受控代理實驗，混合搜尋代理（快取的真實 SerpAPI Google 結果 + 在指定排名位置替換為注入內容；離群查詢回退到即時 SerpAPI，§5）。介於「商業模型 + 手動提供證據」與可複現管線之間；屬於 C／E 之間，取 C（跳過真實檢索排名，假設放置成功）。
- 涉及的引擎和模型：13 個後端（Claude-Sonnet-4.6、Claude-Haiku-4.5、GPT-5.4-mini、GPT-5.4-nano、Gemini-3-Flash/3.1-Pro/3.5-Flash、Kimi-K2.6、Grok-4.3、DeepSeek-V4-Pro/Flash、Qwen3.6-Plus、MiniMax-M2.7），温度 0，ReAct 式工具調用（§5、Table 1）。附加探測用 GPT-5.5。測試日期文中僅見引用「Accessed 2026-05」。
- 樣本：44 個查詢（health/finance/consumer IT/legal 各 11），每個後端 308 個案例（44 查詢 × 6 攻擊條件 + 乾淨基線，由表內數字推得，文中寫 308 cases），總計超過 6,000 個評估案例（§1）；防禦消融 3 個後端；技能探測 10 個 OpenClaw 場景（Claude、GPT-5.4-mini）及 18 個跨生態案例（§6.3）。每案例單次運行（溫度 0）。
- 對照設計：乾淨基線；六個攻擊條件（1A-instr、1A-fact、1B、2A、2B、3；1A/1B/2A 替換第 1 名，2B/3 替換前 3 名）；來源數 N 與排名位置的交叉消融（僅 Gemini-3-Flash）；防禦條件 A（無）、B（OWASP 提示）、C（OpenClaw 預設 harness）。
- 評估方式：LLM 評判（GPT-5.4-mini 評 ASR、OSS、SS；攻擊內容也由 GPT-5.4-mini 生成，經人工審查 264 個檔案；與 Claude-Opus-4.7 在分層樣本上「完全一致」，附錄 E）。攻擊內容為人工審過的合成內容。
- 證據等級：C（商業 LLM 後端，但檢索是代理端快取＋注入，排名與放置由研究者指定）

## 主要發現
1. 後端選擇主導脆弱性：ASR 由 0.0%（Claude-Sonnet-4.6）、0.8%（GPT-5.4-mini）到 31.4%（Gemini-3-Flash）；13 後端平均 13.4%（Table 1）。Gemini 三個變體、DeepSeek-V4-Flash、MiniMax-M2.7 均高於 17%。
2. 攻擊模式（13 後端平均 ASR）：1A-instr 0.3%、1A-fact 2.4%、1B 1.2%、2A 14.2%、2B 24.8%、3 37.2%（Table 1 平均列）。機器層（隱藏 DOM、摘要-頁面不一致）幾近底線；信任信號類為主要攻擊面（§6.1）。
3. 同一載體下，Gemini-3-Flash 命令式隱藏指令 ASR 2.3%，第三人稱偽證據 18.2%——關鍵是負載是否被當作證據吸收，而非隱藏方式（§6.1）。
4. 模式 2B 與 3 依後端而異：Gemini-3-Flash 上 2B 最強（72.7%）；Gemini-3.5-Flash、DeepSeek-V4-Flash 上 Mode 3 最強（75.0%、61.4%）；十個非 Gemini 後端中 Mode 3 ≥ 2B（§6.1）。
5. 來源多樣性驅動 ASR（Gemini-3-Flash，Fig 3）：Mode 2B 隨 N=1,2,3 為 39%、55%、77%；Mode 2A 重複同一來源基本持平；相同 N=3 下排名位置無顯著影響（χ² p=0.27〔2B〕、p=0.89〔Mode 3〕）（§6.2）。
6. 「靜默偏移」：ASR=0 的案例中，Mode 3 有 15.0% 的 ΔOSS≥0.3（Table 2）；成功攻擊平均 ΔOSS +0.692；穩健性與隱蔽性權衡：SS0=0.788 對 SS1=0.393（§6.1）。
7. 自我審核落差（Consumer IT）：成功攻擊上後端給自己的可信度比外部盲審高 +0.312（外部 0.297，自評 0.609）；失敗攻擊上僅 +0.049（Table 3）。
8. 防禦不與後端無關：OWASP 提示（B）使三個後端 ASR 均下降（Gemini-3F 31.4→24.6，DeepSeek-V4F 20.1→12.9，MiniMax 17.4→6.1）；OpenClaw 預設 harness（C）使 Gemini-3F 上升至 34.1%（Mode 2A +31.8）而 DeepSeek/MiniMax 下降（Table 5）。作者未分離具體組件。
9. 代理技能推薦（§6.3，Table 6、7）：乾淨情境 Claude 對 OpenClaw 相關結果 8/10 誤拒；2B 攻擊下 Claude 拒絕全部，GPT-5.4-mini 10/10 輸出偽造技能的安裝指令；跨三個生態（n=18）：Claude 0/18、GPT-5.4-mini 17/18、GPT-5.5 16/18 接受偽造技能。屬機制探測，非人群規模。
10. 穩健後端機制不同（Table 4）：Claude 顯式偵測並標示協同注入（平均搜尋 2.31 次、即時 0.12 次）；GPT 搜尋少，更依賴先驗（1.36 次）；DeepSeek-V4-Pro 搜尋多（4.90 次，ASR 9.1%）——作者的解讀，未做因果檢驗。

## 對應原理和管線階段
- 原理編號：[6, 9, 3, 8, 4]。6：被引用不等於被正確使用（背書 ≠ 檢索可見度）；9：優化與操縱同通道，需要證據層防禦；3：第三方／多來源共識；8：代理技能安裝；4：排名位置在此設定不顯著。
- 管線階段：重排/上下文、生成/引用、吸收/保真、用戶行為/商業。
- 新原理候選：「來源獨立性錯覺」——LLM 用來源數量代理證據獨立性，多個假獨立來源共識比單一權威更有效（可補入原理 6 或 9）。

## 對實踐的含義
- 有實驗支持的做法（攻擊面理解）：多個表面獨立的來源共識（2B/3）最有效；重複同一來源無效；命令式指令效果差，偽證據內容較有效；在此設定中位置不重要。
- 作者建議但未經驗證的做法：來源溯源、跨來源獨立性檢查、引用鏈完整性驗證（§7，屬架構建議，未實驗）；各定價層都應提供基本來源驗證。
- 被證明無效或有害的做法：隱藏 DOM 注入、摘要-頁面不一致、命令式指令（近乎 0）；預設部署 harness 在某些後端會放大攻擊（Gemini-3F +31.8 於 Mode 2A）。

## 局限與效度威脅
- 靜態代理，非即時網路；約 30% 快取結果僅有摘要級內容；假設放置成功（第 1 名或前 3 名被注入）；不含即時排名、新鮮度、競爭性 SEO（Limitations）。
- 每後端僅 44 個查詢、單次運行；以品牌／服務推薦為主，結論不一定外推到其他查詢類型。
- 評判模型與攻擊內容生成器都是 GPT-5.4-mini，並為被測後端之一；僅在分層樣本上與 Claude-Opus-4.7 交叉檢查。
- 技能探測小樣本（10 與 18 案例）。
- 消融（來源數、位置）只用 Gemini-3-Flash。

## 與其他研究的關係
- 支持：PoisonedRAG／SafeSearch 類「不可靠搜索結果」的風險；多來源共識影響推薦；與 2605.24245 一致（都指出證據層而非指令層是攻擊面）。
- 與哪些矛盾：與「位置偏誤主導」的觀點不同（此處排名位置 p=0.27、0.89 不顯著）；與 2605.28017 對比，其指令覆蓋類攻擊在此同樣表現不佳（1A-instr 0.3%）。
