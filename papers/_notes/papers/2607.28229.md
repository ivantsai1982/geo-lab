# 2607.28229 EMBL AI Librarian: Life-Sciences Knowledge Layer for AI Agents

- 日期：2026-07
- 發表狀態：預印本（未註明）
- 作者類型：學術（EMBL / EMBL-EBI 等研究機構；同時是 Europe PMC 的運營方，對自家系統有利益關係）
- 一句話總結：在 Europe PMC 實時搜索上加一層 LLM 編排的「知識層」（子查詢生成 → 段落 BM25 → LLM 句子級篩選），讓 agent 用自然語言取得可引用的證據片段，在 4 組生命科學基準上優於對照檢索。

## 研究問題
現有文獻搜索接口為人設計（關鍵詞語法、返回整篇論文），agent 需學語法、多次搜索、讀全文；能否做一個 agent-first 的自然語言證據接口，且不自建向量索引（§1）？

## 研究設計
- 系統類型：可複現 RAG 管線（垂直領域：生命科學文獻），非通用商業引擎
- 涉及的引擎和模型：Librarian 引擎為自託管 GLM-5；下游 agent 為 GLM-5、Claude Sonnet 4.6（ProClaim）、GPT-5.4 與 GPT-4o（LitQA2/LAB-Bench）；Europe PMC 實時檢索。測試日期未註明（論文 2026-07）。
- 參數：N=7 個子查詢，每個子查詢最多 P=50 篇，全文論文取 k=16 段落進入 Stage 3（§3）。
- 樣本：ScholarQA-Bench（Bio/Neu/Multi 子集）；ProClaim-eval 419 條 claim；open-form LitQA2 91 題；LAB-Bench 四類（公開子集約 80%）（§3.1-3.4）。
- 對照設計：檢索器對比（BM25 on OSDS、PubMed+S2、Web Search、無檢索）；LitQA2 三種設置共用同一 GPT-5.4 骨幹，可隔離檢索器貢獻（§3.3）。ScholarQA 中 Librarian 對比 BM25-OSDS 也是同一 agent。
- 評估方式：Citation F1 與 Prometheus LLM 評分（ScholarQA）；與專家共識的一致率；GPT-4o 做 LLM 評判答案正誤（LitQA2，未見人工驗證說明）；其餘為客觀指標。
- 證據等級：D（完整 RAG 管線，客觀基準為主，部分 LLM 評判；非 GEO 場景）

## 主要發現
1. ScholarQA Citation F1：Synthesis Agent+Librarian Bio 73.8、Neu 79.4、Multi 76.2；同 agent 用 BM25 on OSDS 為 67.0/68.5/72.0；Multi 的 LLM 分數 4.90 vs 4.10（Table 1，§3.1）。相對 OpenScholar-70B 的 Bio 55.9、Neu 63.1 有大幅領先，但作者也承認骨幹更大（GLM-5 約 700B vs 約 70B），不是純檢索貢獻（§3.1）。
2. ProClaim-eval：ProClaim 換用 Librarian 檢索器，agreement 0.75→0.80；單提示 Verifier Agent 用 Librarian 為 0.66，對比 PubMed+S2 的 0.51；OpenScholar 0.43（Table 2，§3.2）。
3. Open-form LitQA2（91 題，GPT-5.4）：無檢索準確率 17.6；Web 搜索 70.3（precision 76.2）；Librarian 78.9（precision 82.6，coverage 92.3→95.6）（Table 3，§3.3）。
4. LAB-Bench：GPT-5.4 macro 準確率 50.5→54.6（+4.2），SeqQA 52.5→63.8（+11.3）；GPT-4o macro 準確率 35.2→35.3 幾乎不變，但 precision 49.0→54.0、coverage 70.2→64.8（更會拒答）（Table 4，§3.4）。
5. DbQA（近似結構化資料庫查找）加入文獻檢索無益：GPT-4o -2.3，GPT-5.4 -1.3（Table 4，§3.4）。
6. 作者主張：強 LLM + BM25 多關鍵詞查詢可匹敵稠密檢索；此為引用他人文獻（§1、§5），本文未做 Librarian vs 稠密索引的直接消融。

## 對應原理和管線階段
- 原理編號：[1, 2, 3, 4, 5, 8]。1：無檢索 vs 有檢索（17.6 vs 70.3/78.9）；2：LLM 生成互補子查詢（N=7）；3：詞彙檢索＋段落級；4/5：句子級證據抽取、返回可引用片段；8：為 agent 而非人設計的接口。
- 管線階段：檢索、重排/上下文、生成/引用
- 新原理候選：「agent 專用知識層／接口」——內容提供方（Europe PMC）在查詢接口上為 agent 做適配（自然語言入口、證據片段出口），這是站點/資料庫層面的 agent 化，與 2607.12056 同屬原理 8 的延伸。另外，LLM 越強，詞彙檢索的相對優勢越大（僅為引用的文獻觀點）。

## 對實踐的含義
- 有實驗支持的做法：把檢索結果切成段落/句子級可引用證據，比返回整篇文章或通用 web 搜索在領域 QA 上更好（LitQA2 78.9 vs 70.3）；多子查詢（別名、欄位）增召回（設計動機，未單獨消融）。
- 作者建議但未經驗證的做法：多輪檢索、擴展到其他 EMBL 資源、多模態（§4，未來工作）。
- 被證明無效或有害的做法：對結構化資料庫查詢類任務加文獻檢索無益（DbQA）。

## 局限與效度威脅
- 覆蓋受限於 Europe PMC，付費全文不在內；單輪檢索；不處理圖、補充材料（§4）。
- 各子任務基線不一致（不同骨幹、不同檢索器），ScholarQA 與 OpenScholar 的比較混入模型規模差異（§3.1 自承）。
- LitQA2 為作者自建 open-form 版本（91 題），用 GPT-4o 評判；樣本小，無置信區間或重複次數。
- LAB-Bench 基線與人類值來自完整集，Librarian 用公開子集（約 80%），不完全可比（Table 4 說明）。
- 作者是被評系統的開發者。

## 與其他研究的關係
- 支持哪些研究的結論：支持 BM25 + 強 LLM 多查詢的可行性（引用 PI-SERINI、SAGE 等，§5）；與 BioContextAI 報告 MCP 優於 web search 方向一致（§5，引用）。
- 與哪些研究的結論矛盾：無直接矛盾；對「稠密索引必要」的假設有質疑。
