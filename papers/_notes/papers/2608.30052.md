# 2608.30052 The Language of the Question Selects the Market: Query Language and Exit IP as Separable Factors in Commercial Recommendations from a Generative Search Interface

- 日期：2026-08
- 發表狀態：預印本（arXiv cs.IR，2026-08-30；未註明投稿）
- 作者類型：GEO 或 AI 可見度服務商（單一作者為 Rankfor.AI 的 CEO，該公司出售 AI 可見度測量；文中已聲明利益衝突並由該公司實物資助）
- 一句話總結：對登出狀態的 ChatGPT 網頁介面問商業推薦，查詢語言決定會不會出現本地供應商，出口 IP 決定「哪個國家的市場」被當作用戶市場，兩者可分離；同時頂部推薦本身在相同提示下不穩定。

## 研究問題
1. 生成式介面對商業問題的頂部推薦有多穩定？2. 查詢語言與用戶地理（出口 IP）哪個決定會不會出現本地供應商？3. 兩者能否分離？4. 換一個品類，效應是否仍存在（負對照）？

## 研究設計
- 系統類型：真實商業引擎（登出的 ChatGPT 網頁 UI），並以 OpenAI API 的 gpt-5.6-terra（有/無 web_search）作介面 vs API 對照
- 涉及的引擎和模型，以及測試日期：ChatGPT 網頁 UI（模型未披露）＋ API gpt-5.6-terra；2026-08-29 與 08-30；出口 IP 為柏林、奧斯陸、伊斯坦布爾、塔林（住宅），以 ipinfo.io 驗證
- 樣本：11 個 cell，234 個可用運行（另有 12 個手工採集的運行被丟棄並重採），每個 cell 相同提示重複 6 次，每次新瀏覽器上下文；柏林/奧斯陸/API 各問 6 個品類提示，其餘只問兩個對比提示：自由職業者記帳軟件（處理組）與小型行銷公司項目管理軟件（負對照）（§3.1）
- 對照設計：一次改一個因子（語言 × 出口 IP × 介面）；相同 IP 下換語言；相同語言下換 IP；負對照品類（事先固定，預期無本地供應商，結果證明預期錯了）
- 評估方式：客觀。本地/他國/全球三類品牌名單事先固定、區分大小寫匹配；每一行來源文本人工審讀（§3.2）。統計只有 Fisher 精確檢驗。
- 證據等級：B（真實商業引擎、重複運行、多語言多地區；但單一日期、單模型、每品類一個提示、每 cell 只有 6 次）。

## 主要發現（逐條列出，附數字和出處節號）
1. 頂部推薦不穩定：6 次相同運行中，柏林介面、奧斯陸介面、API（開搜索）、API（關搜索）都是 6 個提示中有 4 個的第一推薦變化；比率相同，但不穩定的提示集合並不完全一致；會計與 HR 在所有臂都不穩定（§4.1）。這說明不穩定不是瀏覽器介面造成的。
2. 語言而非地點決定本地供應商是否出現：查詢語言是出口國官方語言的 4 個 cell 中，全球供應商僅在 24 次運行中的 1 次出現；用英語問，伊斯坦布爾與塔林的 12 次運行中本地供應商 0 次（§4.2）。Fisher：Fiken（挪威）p=0.0152、Lexware（德國）p=0.0606（雙側）；單側 0.0076/0.0303，合併 χ²=16.75（df=4），p=0.0022；土耳其與愛沙尼亞為邊界情形，未納入合併（§4.2）。表 2：奧斯陸英語 Fiken 1/6，挪威語 Fiken/Tripletex/Conta 均 6/6；塔林愛沙尼亞語 Merit Aktiva 6/6。摘要寫「global brand won 1 of 24 runs」，正文（§4.2）寫「appeared」，此處以正文為準。
3. 三層結構：塔林一條連接上，愛沙尼亞語（官方）本地供應商 Merit Aktiva 6/6、SimplBooks 5/6、Directo 4/6，全球 1/6；俄語（少數語言）Merit Aktiva 4/6、SimplBooks 4/6、Xolo 3/6，全球 6/6；英語本地 0/6，全球 6/6（表 3）。愛沙尼亞語與俄語運行全部提到愛沙尼亞；英語 2/6 提到，說明「知道地點」不等於會推薦本地供應商（§4.3）。
4. 語言與地點可分離：土耳其語問題，伊斯坦布爾 IP 得到 Paraşüt 6/6、Logo 6/6、Mikro 3/6；柏林 IP 得到 Lexware 5/6、sevdesk 5/6、FastBill 4/6，土耳其供應商各只 1/6，答案仍是土耳其語，且開頭說「如果你在德國作為自由職業者」（表 4）。俄語從塔林問，名字來自愛沙尼亞而非俄羅斯供應商，在第二對語言/國家上重複（§4.4）。英語不是中性對照：在伊斯坦布爾英語 0 個土耳其供應商（§4.4）。
5. 負對照無效應：項目管理軟件在所有 cell 中本地供應商 0 個，全球是 ClickUp、Asana、Teamwork 等（表 6）；作者原先預期「有本地供應商就會有語言效應」被否證，改為推測「該品類是否受國家監管（VAT、電子發票）」，這只是待檢驗的推測，未收集第三個品類來分離（§4.6）。
6. API：有 web_search 的 36 次運行共 200 條引用（5.56/答案）、48 個網域、170 條帶 utm_source=openai；無搜索的 0 條引用（表 5）。API 沒有用戶地理，英語問題返回美國答案（§4.5）。
7. 作者引用其先前工作（非本文實驗）：對 12,933 個答案的方差分解中，查詢語言佔單次回答方差 26.5%、品牌身份佔 1.5%（§2.6，引自 Żatuchin 2026c）。

## 對應原理和管線階段
- 原理編號：[1, 3, 7]。7：單次回答是分佈中的一次抽樣，且語言與地區是測量的設計因子；3：查詢語言與地理影響召回範圍（機制未證明）；1：模型知道用戶在愛沙尼亞卻不推薦本地供應商，提示不是知識缺失。
- 管線階段：觸發、檢索、生成/引用（實現機制在論文中未識別）
- 新原理候選：「語言與地理作為市場閘門」——查詢語言決定候選供應商集合被整體替換（不是重新排序），出口 IP 決定是哪個市場；用英語測量會看不到本地競爭對手。這個機制是否來自檢索、指令調優或名單構造，作者明說無法區分（§5）。

## 對實踐的含義
- 有實驗支持的做法：在目標市場的語言下測量可見度；測量報告中需標註查詢語言、出口 IP、是否有搜索；同一提示多次重複。
- 作者建議但未經驗證的做法：把語言當設計因子而非翻譯步驟；用英語測量本地市場會誤判（§5）；未來測試更多國家、每 cell 20–30 次運行、登入狀態（Conclusion）。
- 被證明無效或有害的做法：截圖單次回答當證據（作者認為是「測量噪聲」，基於 4/6 提示不穩定的結果）。

## 局限與效度威脅
- 每 cell 6 次：作者估計能以約 88% 的機率偵測到主導率 70% 的贏家，主導率 90% 的只有約 47%（Limitations）；「6/6」不等於確定性。
- 單一模型（網頁介面模型未披露）、每品類一個提示、8 個非塔林臂連續採集於一個晚上，時間段未控制。
- 出口 IP 來自 VPN/住宅連接，其他地理信號（時區、Accept-Language 等）未被隔離（筆記者的觀察，論文未詳述）。
- 英語不對稱未解釋（柏林、奧斯陸英語本地品牌出現 1–2 次，伊斯坦布爾、塔林 0 次）；作者的一項預測（塔林英語應混合）失敗。
- 作者為 AI 可見度測量公司 CEO，結論涉及自身業務，作者已聲明；介面單元格沒有可檢查的引用，因此「檢索造成語言效應」的替代解釋無法排除（§2.4）。
- 品類僅記帳（處理）與項目管理（對照），監管解釋沒有第三個品類支持。

## 與其他研究的關係
- 支持哪些研究的結論：LLM 存在英語默認、文化主導（Wang 2023 等，文中引用）；多語言 RAG 的檢索不對稱（Wu 2024、Chirkova 2024，文中引用，作為替代解釋）；LLM 輸出非確定性（Atil 2024）。
- 與哪些研究的結論矛盾：與傳統搜索審計「個性化只是重排、結果集大體共享」（Hannák 2013）不同，這裡是候選集替換；與品牌流行度偏見（Kamruzzaman 2024）預測的全球品牌佔優並不矛盾，但在本地語言下反轉。

## 值得到從業者社群（Reddit）驗證的問題

- 你們的可見度追蹤工具是否標註查詢語言和地區？換 VPN 出口後結果是否明顯變化？
- 受監管品類（稅務、法律、金融）與非監管品類（項目管理、設計軟件）的本地化差異是否存在？
