# 2609.02964 When Optimization Becomes Manipulation: Defending Generative Search against Malicious Generative Engine Optimization

- 日期：2026-09
- 發表狀態：預印本（未註明；arXiv v1，2026-09-02，cs.CR）
- 作者類型：學術（中國科學院大學、中關村實驗室）
- 一句話總結：提出兩階段防禦 GEO Defender（偏好式 Shield Reranker + 免訓練經驗庫 TFSG），在保持事實不變的 GEO 攻擊下把平均攻擊成功率從 50.32% 降到 6.20%，同時保留 94.12% 的良性證據使用。

## 研究問題
GEO 改寫後的文檔保持事實一致、放大的特徵（統計、引用、權威語氣）也是優質內容的特徵，事實核查與困惑度過濾失效；引擎方能否沿「重排 → 生成」全鏈防禦，並避免過度防禦？（Introduction）

## 研究設計
- 系統類型：可複現 RAG 管線（Tavily Search 取十篇候選、Qwen3-Reranker-0.6B 重排取 top-5、LLM 生成帶引用答案）
- 涉及的引擎和模型，以及測試日期：目標 LLM 為 GPT-5.5、Claude Opus 4.8、DeepSeek-V4-Pro、Kimi K2.7 Code、GLM-5.2（參考文獻存取日期 2026-07-29，實驗日期未明述）；七種 GEO 攻擊：AgenticGEO、AutoGEO、MAGEO（構建時可見）；GEO、GEO-SFE、IF-GEO、RAID-GSEO（未見）；GPT-5.5 為評判
- 樣本：GEO-DefenseBench：100 個查詢組（取自 GEO-Bench），每組一篇來源文檔由七種方法各改寫一次，共 652 個攻擊注入實例；構建集 12 組 x 3 方法 = 36 實例，測試集 88 組 x 7 = 616 實例（Table B.1）
- 對照設計：Non-Defense、PPL-Filter（GPT-2，閾值 45.63）、Static Safety Prompt、GEO Defender；模組消融；按查詢分組切分並含未見攻擊；跨 LLM 遷移經驗庫
- 評估方式：客觀指標 ASR（答案引用了攻擊文檔的比例）；LLM 評判 ASI（0–100 語義影響）、BER（良性證據使用相對乾淨參考答案）、成對答案品質（GPT-5.5，未見人工驗證）
- 證據等級：D（可複現完整 RAG 管線，含檢索、重排、生成；但評判依賴 LLM、攻擊文檔為合成改寫）

## 主要發現（逐條列出，附數字和出處節號）
1. 未防禦平均 ASR 50.32%、ASI 35.95%、BER 87.80%；GEO Defender 為 6.20% / 3.89% / 94.12%；各模型 ASR 5.03–7.79%（Table 1）。
2. PPL-Filter 幾乎無效：平均 ASR 50.03%（Non-Defense 50.32%）。616 個攻擊文檔中僅 15 個被閾值標記，卻誤標 252/5,544（4.55%）良性文檔；淨減少僅 4 個曝光的攻擊文檔（Table B.2）。
3. Static Safety Prompt 效果有限且有代價：平均 ASR 46.98%，BER 降到 83.31%（GPT-5.5 上 89.66 降至 71.67）；作者推測是整體降低了對證據的使用（Table 1，屬解釋性推論）。
4. 消融（GPT-5.5）：僅 Shield Reranker ASR 10.06%、BER 98.79%；僅 TFSG ASR 10.39%、BER 77.99%；兩者合併 5.03%、BER 86.68%（Table 2）。
5. 對未見攻擊具泛化：GEO、RAID-GSEO 上表現與見過的方法相當，GEO-SFE 與 IF-GEO 變異較大但仍有大幅保護（Figure 3，僅圖示）。
6. 經驗庫跨模型遷移：所有源-目標對 ASR 4.06–9.09%、ASI 2.23–5.40%；DeepSeek 的經驗庫使 Claude Opus 4.8 ASR 由 5.52 降至 4.06（Figure 4、Table C.2）。
7. 經驗庫構建成本低：僅 36 個構建實例，第一輪優化帶來最大降幅（Figure 5、Table A.3）。
8. 答案品質：相對乾淨參考答案的宏平均變化 -0.01（[-2,2] 尺度）；GPT-5.5 -0.12（CI [-0.21, -0.03]，唯一區間不含 0），70.45–76.79% 答案被判「相當或更好」（Table C.1）。
9. 未防禦時，616 個實例的 top-5 中有 345 個含攻擊文檔（Table B.2），即 GEO 改寫使文檔更容易進入證據集。

## 對應原理和管線階段
- 原理編號：[9, 4, 5]。9：優化與操縱走同一通道（論文明確主張兩者差別在意圖而非機制），並提出防禦機制；4：進入上下文（top-5）與相關性排序決定可見度；5：GEO 放大的統計、引用、權威語氣等結構特徵。
- 管線階段：重排/上下文、生成/引用、吸收/保真
- 新原理候選：無。可補充「過度防禦」（良性證據損失）作為防禦評估維度。

## 對實踐的含義
- 有實驗支持的做法：（引擎方）在凍結重排器上加 LoRA 偏好殘差以降權 GEO 改寫；用外部自然語言經驗庫指導黑盒 LLM 的來源使用。
- 作者建議但未經驗證的做法：兩模組可獨立或聯合部署；（內容方視角的推論，非論文結論）僅靠 GEO 特徵在有此類防禦的引擎中可能被降權。
- 被證明無效或有害的做法：PPL 過濾（幾乎不降低攻擊、誤傷良性）；靜態安全提示（降低攻擊同時降低良性證據使用）。

## 局限與效度威脅
- 正文與附錄未見獨立的「局限」章節；以下為讀者評述：
- 攻擊文檔為七種優化器對同一篇來源文檔的離線改寫，只替換候選中一篇；未含針對 Shield Reranker 的自適應攻擊者。
- 防禦與攻擊同分佈（GEO-Bench 查詢、Tavily 檢索），構建集僅 36 實例；測試僅 88 個查詢組。
- ASR 定義為「被引用」，並非答案是否被誤導；ASI 與品質由 GPT-5.5 評判且無人工驗證，而 GPT-5.5 同時是受測對象之一。
- 「攻擊」指保留事實的 GEO 改寫本身，被降權的可能是更優質的內容；優質內容損失僅以 BER 近似衡量。
