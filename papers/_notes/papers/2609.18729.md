# 2609.18729 "If I Had to Buy Just ONE: Galaxy S26 Ultra" Auditing AI-Generated Product Recommendations

- 日期：2026-09
- 發表狀態：預印本（未註明）（arXiv cs.CY；AAAI 風格格式，未註明會議）
- 作者類型：學術（馬斯特里赫特大學、烏特勒支大學、蘇黎世大學；聲明未受三星資助）
- 一句話總結：以真實用戶商品查詢審計 ChatGPT、Gemini 與 Google AI Overviews 的商品推薦，發現各系統表達確定性差異巨大，重複請求的產品與來源都不穩定，且 API 觀察不能代表消費者介面。

## 研究問題
RQ1 商品推薦在不同 AI 聊天機器人間及重複請求間如何變化；RQ2 各系統為商品推薦顯示什麼來源；RQ3 能否用 API 來審計面向消費者的介面（§Introduction）。

## 研究設計
- 系統類型：真實商業引擎（消費者網頁介面，登出狀態）+ 對應 API 配對
- 涉及的引擎和模型，以及測試日期：ChatGPT 介面與 API（gpt-5.6-luna，介面自報，作者無法驗證）；Gemini 介面與 API（gemini-3.5-flash-lite）；Google AI Overviews。AIO 於 2026-09-04（336 次）與 09-05（15 次）收集；固定荷蘭住宅代理 IP（§Audit Methodology）。
- 樣本：CONSUMERQ = 2,528 條經人工確認的真實商業建議查詢（來自 LMSYS-Chat-1M 與 WildChat-1M，過濾器精度 89.0%，三人標註 α=0.65）；審計子集為 117 條實體商品查詢（中位 8 詞）× 3 次重複 × 5 條件 = 1,755 次觀察，1,536 次有回應；AIO 351 次搜索中僅 134 次（38.2%）有可解析內容。
- 對照設計：介面請求與 API 請求以中位 0.17 秒間隔配對（702 對）；重複之間相隔中位 1.8–2.5 小時；每次新瀏覽器設定檔、無歷史。
- 評估方式：LLM 標註（gpt-5.6-luna，依人工金標與編碼手冊驗證，α 見附錄）+ 客觀指標（Jaccard 重疊）；來源類型分類由 gpt-5.5 完成但未系統驗證，作者稱為探索性。
- 證據等級：B（真實商業引擎、重複測量；但僅 3 次重複、單一地區）

## 主要發現
1. 第一人稱推薦：ChatGPT 79%、Gemini 7%、AIO 2%；宣稱某產品為「最佳」：73% / 43% / 48%（§RQ1、圖2；基數為含產品的回應，700/836）。
2. 提問澄清：Gemini 94%、AIO 97%、ChatGPT 82%（§RQ1）。
3. 重複一致性：產品集 Jaccard，AIO 0.421、Gemini 0.287、ChatGPT 0.178；ChatGPT 自身重複之間的重疊與其和 AIO 的重疊無顯著差異（§RQ1、圖4）。「最佳」標示在重複中改變的查詢佔 27–40%。
4. 介面間來源：ChatGPT 與 Gemini 同一查詢平均共享 5.4% 域名，76.7% 的比較沒有任何共同域名；ChatGPT–AIO 5.2%；Gemini–AIO 9.8%；頁面層重疊 2.4–6.5%（§RQ2）。
5. 重複請求持續帶出新來源：ChatGPT 平均域名數由 1 次的 2.65 增至 3 次的 5.56（頁面 3.33→7.70）（§RQ2）。單介面內重複域名重疊：ChatGPT 26.0%、Gemini 29.8%、AIO 45.9%。
6. 來源類型：ChatGPT 最常見 techradar.com 13.8%、tomsguide.com 12.0%；Gemini 為 pcmag.com 12.4%、reddit.com 8.0%、youtube.com 6.9%；AIO 為 reddit.com 35.0% 與 youtube.com 30.0%。編輯／評測類來源占域名 ChatGPT 56.7%、Gemini 45.2%、AIO 25.4%（探索性分類）（§RQ2）。
7. API 非介面代理：介面與 API 域名重疊 ChatGPT 12.0%、Gemini 14.8%；無共同域名的比例 60.9% 與 43.4%（§RQ3）。ChatGPT API 偏向廠商域名（nvidia.com、asus.com），介面偏向科技媒體；Gemini API 的 youtube.com、reddit.com 出現機率分別高 44.4 與 29.1 個百分點。
8. 來源分層：ChatGPT API 搜索平均返回 13.48 域名、37.38 頁，最終引用僅 2.62 域名、3.22 頁；引用頁 100% 出現在搜索返回集中（§RQ3）。

## 對應原理和管線階段
- 原理編號：[3, 6, 7, 9, 10]。3：來源池因引擎而異；7：可見度是隨機分佈，單次觀察不足；9：作者提示廣告與商業利益衝突（僅為背景，未實測）；10：AI 推薦影響購買相關流量（僅背景引述）。
- 管線階段：檢索、生成/引用、用戶行為/商業（僅框架）
- 新原理候選：「觀察層次不等價」——搜索返回集、最終引用、面板來源、API 欄位是不同的可見層；審計對象必須明示層次。

## 對實踐的含義
- 有實驗支持的做法：測量 AI 可見度應使用消費者介面、重複多次並記錄來源層；不同引擎的可見來源幾乎不重疊，需分引擎優化與監測。
- 作者建議但未經驗證的做法：審計者、NGO 與監管者應採用介面觀察；作者也警告結果可能被用於優化，未給出優化建議。
- 被證明無效或有害的做法：用 API 結果代表消費者所見；單次回應代表性。

## 局限與效度威脅
- 117 條實體商品查詢，每條 3 次；排除高度具體與含地理限制的查詢（Limitations）。
- 單一地點（荷蘭 IP），查詢主要為英文；LMSYS/WildChat 用戶偏科技（Data and Methodology）。
- 未涵蓋 Claude 等；AIO 僅 38.2% 有內容，結論僅適用於出現 AIO 時。
- ChatGPT 介面模型未公開，API 模型只是近似，故介面與 API 差異不能歸因於接入方式（作者明說）。
- 產品名稱未歸一化，重疊為下限；LLM 標註與來源分類的驗證有限。
- 沒有證據顯示所顯示來源實際影響推薦內容（作者明說）。

## 與其他研究的關係
- 支持哪些研究的結論：介面與 API 響應有差異（Schatto-Eckrodt 2025 等，文中引述）；生成式搜索響應不一致（Grossman 2026）。
- 與哪些研究的結論矛盾：無明確矛盾。
