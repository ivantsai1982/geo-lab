# 2609.19244 Characterizing Web Search by Conversational LLM Agents: From Search Decisions and Strategies to Results and Responses

- 日期：2026-09
- 發表狀態：預印本（未註明）（arXiv cs.AI；ACL 風格格式，未註明會議）
- 作者類型：學術（馬克斯普朗克軟體系統研究所、波鴻魯爾大學等；含一位 Microsoft 作者）
- 一句話總結：結合 613 位用戶捐贈的真實對話（in vivo）與四家平台 API 的控制重放（in vitro），逐階段刻畫 ChatGPT、Claude、Grok、DeepSeek 的搜索決定、查詢策略、結果域名偏好與回答落地程度。

## 研究問題
1. 代理何時決定調用網頁搜索？2. 如何查詢搜索工具？3. 如何利用搜索結果合成回答？（§1）

## 研究設計
- 系統類型：真實商業引擎的田野日誌（數據捐贈）+ 商業模型 API 控制實驗（有搜索工具）
- 涉及的引擎和模型，以及測試日期：ChatGPT、Claude、Grok、DeepSeek 的真實用戶對話（時間範圍約 2022-11 至 2026-05，圖1）；in vitro：GPT-5.3-chat、Claude Sonnet 4.6、Grok-4.3、DeepSeek-v4-flash；另比較 GPT-4.1-mini、o4-mini（表2）。
- 樣本：in vivo 共 171,264 場對話、613 位用戶（表1：ChatGPT 143,730 場/310 人、Claude 9,267/102、Grok 9,005/100、DeepSeek 9,262/101）；含搜索的回合 ChatGPT 42,273、Claude 1,696、Grok 3,004、DeepSeek 1,730。in vitro 用同一組 1,000 條用戶首句（已去除個人資訊）。
- 對照設計：in vitro 同一批 1,000 提示跨模型；有搜索 vs 關閉搜索的同提示對比（表3）；把一個 GPT 模型的系統提示作為 developer prompt 複製到另一個模型，分離「harness 指令」與「模型自身決策」（表4）。
- 評估方式：LLM 評判（事實性、完整性、相關性；與人工「±1 內」一致 67–77%）；主張蘊含由平台專屬評判模型完成，人工一致 93%；查詢具體性人工一致 >90%。
- 證據等級：B（真實商業引擎 + 日誌，含重複與多平台；但無隨機對照、多為觀察性，主要依賴 LLM 評判）

## 主要發現
1. 搜索使用隨時間上升，各主題差異大（如旅遊高於健康）（§3.1、圖1、圖3）。
2. 同一批 1,000 提示：GPT-5.3-chat 只對 140（14%）調用搜索，Claude 對 825（83%）（§3.1、表3）。Grok-4.3 766，DeepSeek-v4-flash 584。
3. harness 與模型都影響決策，但模型自身決策佔主導：o4-mini 在原生指令下 634 次，換成 GPT-5.3-chat 的指令降至 478，仍遠高於 GPT-5.3-chat 的 140–169（表4）。
4. 搜索不一定提高品質：GPT-5.3-chat、Grok-4.3、DeepSeek 明顯受益；Claude Sonnet 4.6 儘管大量搜索，只有混合效果。模型未調用搜索的提示分數高於需要搜索的提示（如 GPT-5.3 事實性 3.97 vs 3.50），作者解讀為模型善於判斷不需搜索（表3；LLM 評判）。
5. 查詢策略：in vivo 每提示中位網頁查詢數 Claude 2、Grok 4；ChatGPT、Grok、DeepSeek 並行 fan-out，Claude 每輪只發一個查詢，因此迭代更深（§4.1）。in vitro 僅 GPT-5.3 有 fan-out（§4.1）。
6. 查詢改寫：近 80% 用戶提示超過 20 詞，而網頁查詢多在 10–15 詞以內，但仍長於傳統人類查詢（2–4 詞）；首輪查詢新詞約 80% 來自對話歷史、約 30% 來自最新提示；後續輪次逐步加入時間、地點、實體約束，具體性上升（§4.2、圖5–7）。
7. 每查詢返回 URL 數：ChatGPT 約 14.06、Claude 9.19、Grok 8.95、DeepSeek 5.46；每提示累計 ChatGPT 43.24、Grok 40.68、Claude 16.61、DeepSeek 14.37（表5）。
8. 域名偏好：reddit.com、youtube.com 在 ChatGPT 與 Grok 結果中居前，DeepSeek 也高，Claude 中「完全缺席」；xiaohongshu.com 僅在 DeepSeek 突出。前十域名占比 in vivo：ChatGPT 21.3%、Grok 32.3%（§4.3、圖8）。
9. 引用率（被引的搜索結果占比）in vivo：ChatGPT 13.3%、Claude 19.9%、Grok 1.8%、DeepSeek 34.1%；in vitro：GPT-5.3 10.6%、Claude 39.7%、Grok-4.3 25.5%（表6）。被引 URL 中僅不到 1% 至 5% 來自參數知識；幻覺引用 1–2%（§5.1）。
10. 被引 URL 的域名 Tranco 排名整體高於搜索結果，說明偏好高權威（受歡迎）域名（§5.1、圖9）。
11. 主張落地：關聯引用支持 30–46% 的主張；未被引用但出現在搜索結果中的 URL 支持 14–53% 的主張；15–20% 以上主張無法落地，事實性最低（ChatGPT 2.84，對比關聯引用 3.47）（§5.2、圖10）。

## 對應原理和管線階段
- 原理編號：[1, 2, 3, 6, 7]。1：搜索觸發依平台／模型與 harness 而異；2：fan-out 與迭代改寫；3：平台專屬搜索索引與域名偏好；6：被使用的來源不等於被引用（14–53% 主張基於未引用結果）。
- 管線階段：觸發、檢索、生成/引用、吸收/保真
- 新原理候選：「harness（系統提示）與模型自身共同決定搜索觸發」；「隱形使用」——被用於生成但未被引用的來源（引用低估影響力）。

## 對實踐的含義
- 有實驗支持的做法：（觀察性）每個平台的搜索索引偏好不同，需分平台看可見度；被引 URL 傾向高權威域名；查詢會逐步加入時間、地點與實體詞，因此內容涵蓋具體實體與時間資訊可對應後續查詢（此為對觀察的推論，未直接驗證）。
- 作者建議但未經驗證的做法：設計者應優化與評估整條搜索生命週期，特別是來源歸屬。
- 被證明無效或有害的做法：「更多搜索 = 更好回答」不成立（Claude 混合效果）；僅看引用會低估來源的實際使用（14–53% 主張來自未引用結果）。

## 局限與效度威脅
- 觀察性對話，無法看到內部推理、排序或專有檢索管線；行為可能反映 harness 而非模型本身。
- 用戶樣本（613 位捐贈者）與語言（主要英文）可能不代表整體；in vitro 只用首句 1,000 條。
- 多項分析依賴 LLM 評判（質量分數僅 67–77% 在 ±1 內一致）；查詢詞來源歸因無法完全區分檢索與參數知識；「參數引用」為近似。
- 主張落地的「未落地＝來自參數知識」僅為推測；未研究用戶信任與行為。
- in vivo 各平台用戶提示不同，跨平台直接比較有限，因此作者用 in vitro 補充。

## 與其他研究的關係
- 支持哪些研究的結論：不同引擎索引與引用來源差異大（與本批 2609.18729 一致）；引用與實際使用不等同（呼應 2609.15164 對「可見引用信用」的區分）。
- 與哪些研究的結論矛盾：無明確矛盾（Reddit 在 ChatGPT/Grok 結果中占比高，與 2609.14575 中 GPT 強制搜索條件下 Reddit 幾乎不被引用的結果，因查詢類型與資料來源不同而看似不一致，作者並未討論）。
