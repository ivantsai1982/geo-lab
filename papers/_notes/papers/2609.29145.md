# 2609.29145 Claim-Gated Source-Risk Auditing for Generative Search

- 日期：2026-09
- 發表狀態：預印本（未註明）
- 作者類型：業界（作者隸屬 Google、Sony、Intuit；致謝北京理工大學珠海項目）
- 一句話總結：提出對「查詢-來源-答案」三元組的審計規格，判斷答案是否遺漏了會改變解讀的來源關係（如聯盟收益或所有權），並以合成資料驗證實現與規格一致（81/81），未做任何真實網頁或準確度測試。

## 研究問題
生成式搜索的答案可能引用了有支持力的段落，卻沒有披露該來源與被查詢目標之間的關係（如付費聯盟評測）。這種遺漏如何被明確定義、可追溯、可審計（第 1 節）。

## 研究設計
- 系統類型：模擬或理論（規格加合成 fixture 的一致性測試）
- 涉及的引擎和模型，以及測試日期：無真實引擎；Python 3.13.5 標準庫；不用任何預訓練模型或網絡。
- 樣本：完整枚舉 {0,1,U}^4 共 81 個狀態（1 個陽性、15 個陰性、65 個未決）；12 類缺陷 x 16 條完整記錄 = 192 個畸形記錄（第 4 節）。
- 對照設計：與 Support-only、Relationship-only、Disclosure-only 三個規則投影及各消融比較，並加相同完整性 guard（Table II）。
- 評估方式：客觀（與規格導出的 oracle 比對）；無人工標籤，無 LLM 評判。
- 證據等級：E（純規格/合成，無真實系統；論文自己聲明不是偵測器準確度）

## 主要發現（逐條列出，附數字和出處節號）
1. 四謂詞（I 關係、A 採用、M 實質性、D 披露）完整案例終點：I·A·M·(1−D)；任一為 U 則整體為 U。(1,1,1,0) 為遺漏（第 3.1 節）。
2. 復現全部 81 個三態組合；拒絕 192/192 畸形記錄；證據移除 216/216 保持未決；支持度切換 81/81 不改變終點；dQ 掃描 891/891 不改變終點（Table III、第 4.D 節）。這些數字共享基礎狀態，不是獨立觀察。
3. 無 guard 時 Support-only 漏掉唯一陽性並對 65 個未完整狀態全部給出決斷；Relationship-only 與 Disclosure-only 各在 7 個已決狀態上不一致、對 38 個未完整狀態給出決斷（Table II）。加相同 guard 後不當決斷消失，但已決不一致仍在（第 4.B 節）。
4. 短路策略可決斷 66/81 狀態，完整案例契約只決斷 16/81；代價是覆蓋率（第 4.C 節）。這是合成覆蓋計數，不是部署比率。
5. 微基準：端點 0.49 微秒/tuple，完整記錄檢查 51.20 微秒/tuple（不含 I/O、檢索、生成、標註）（第 4.E 節）。

## 對應原理和管線階段
- 原理編號：[6, 9]。6：引用支持與來源關係是不同問題（被引用不等於被正確解讀）；9：來源披露與操縱防禦。
- 管線階段：吸收/保真、生成/引用
- 新原理候選：「來源關係披露缺失」，即答案可事實正確、引用有支持，但因缺少所有權/聯盟披露而誤導；這是作者的規格性主張，不是實驗現象。

## 對實踐的含義
- 有實驗支持的做法：無（僅證明實現與規格一致）。
- 作者建議但未經驗證的做法：PASS/CONTEXTUALIZE/REVIEW/ABSTAIN 政策界面；獨立雙標註、凍結閾值、配對答案評估（第 5 節）。
- 被證明無效或有害的做法：無實證；僅在形式層面顯示只看引用支持或單一謂詞會丟失資訊。

## 局限與效度威脅
- 全部為合成資料，無真實網頁、無人工標籤；oracle 與被測規則同源，非獨立語義真值（第 4.A 節）。
- 未證明謂詞（尤其實質性 M）能被人一致標註；未估計遺漏盛行率或用戶效益。
- 完整案例策略可能導致審核負擔（作者自列為可證偽條件）。
- 對 GEO 只有間接關聯；審計對象是答案披露而非可見度。

## 與其他研究的關係
