# 2610.24081 Location, Location, Generation: Where You Ask Matters for Generative Engine Optimization

- 日期：2026-10（arXiv v1，2026-10-16，cs.IR）
- 發表狀態：預印本（未註明投稿；使用 ACM 模板與 CCS 分類，但沒有標註會議）
- 作者類型：學術（University of Toronto 兩位作者）。注意：第二作者 Koudas 也是 2509.08919 的作者，教材來源檔把 2509.08919 標為「混合作者，與服務商有關聯」；本文沒有利益衝突聲明。作者公開了問題、代碼和回答（§6）。
- 一句話總結：在同一受控設計中分開操縱「應用宣告的地點」和「網路位置」，發現 ChatGPT（API）只讀宣告地點、可細到城市，Gemini（API）只讀網路所在國家、細不到城市；地點會換掉大部分引用來源和被推薦商家，Gemini 連與地點無關的問題也被換掉。

## 研究問題

- RQ1：用戶地點會不會改變生成式引擎引用的來源？哪些類型的問題會受影響？（§1）
- RQ2：地點從哪個通道進入：應用**宣告**給引擎的地點，還是引擎從網路**推斷**的地點？如果是宣告地點，起作用的是模型把地名寫進搜索詞，還是搜索後端本身？（§1）
- RQ3：改變的是什麼：本地來源還是全國性來源？答案推薦的商家會不會跟著換？（§1）

## 研究設計

- 系統類型：真實商業引擎，經官方 API 呼叫並開啟聯網檢索（不是消費者網頁或 App 介面）。
- 涉及的引擎和模型，以及測試日期：
  - ChatGPT：gpt-5.4-mini，Responses API 加 web search 工具；宣告地點透過該工具的「approximate user location」參數傳入（§3 E1）。穩健性檢查另用完整版 gpt-5.4（§3、§4 Robustness）。
  - Gemini：gemini-3.1-flash-lite，開啟 Google Search grounding（§3 E2）。
  - 時間：作者稱測量描述的是 2026 年 10 月的引擎（§5 Limitations）。
- 樣本：
  - 300 個英文問題，作者自寫，分 10 個商業主題（居家服務、醫療、金融、保險、電信、餐飲、零售、汽車、旅行、公共服務），三組各 100 題：「附近」型（如 best plumber near me）、答案取決於地點型（價格、法規、供應商、天氣，如車輛銷售稅多少）、非本地型（如 best robot vacuum）。**沒有任何一題寫出地名**（§3 Questions and locations）。
  - 19 個宣告地點：15 個在規模和地區上各不相同的美國城市，加上倫敦、多倫多、悉尼、都柏林 4 個其他英語國家城市（§3）。
  - **E1 宣告地點**：每題送 ChatGPT，每個城市作為宣告地點、外加一個「不宣告」條件，每個設定問兩次（雙胞胎重複）。兩個臂：模型自行決定是否搜索（照原句問）；以及在問題前加「Search the web:」，保證每題都有來源。E1 共 24,000 個回答，全部從同一網路發出（§3）。（按設計推算：300 題 × 20 個地點條件 × 2 臂 × 2 次 = 24,000，與論文數字一致；這個乘法是筆記者自行核對，論文沒有寫出算式。）
  - **E2 網路位置**：每題不宣告地點，送 ChatGPT（「Search the web:」臂）和 Gemini，每個各問兩次，分 6 個網路會話：作者在加拿大的自有連線、VPN 出口紐約／洛杉磯／倫敦／悉尼，以及三天後再用自有連線測一次漂移。共 7,200 個回答（§3）。（300 × 2 引擎 × 6 會話 × 2 次 = 7,200。）
  - 合計 24,000 + 7,200 = 31,200 個回答（摘要）。另有穩健性檢查：完整版 gpt-5.4，60 題（每組 20 題）× 6 個地點，共 720 個回答（§4 Robustness），不在 31,200 之內。
  - Gemini API 也接受宣告座標，但作者只在**試點**中測過，稱「沒有效果」；E2 不宣告地點。也就是說，「Gemini 忽略宣告地點」的證據是試點，正文沒有給出試點的數字（§3 E2）。
- 對照設計：
  - 噪音基線：同題、同設定、同會話的兩次回答（雙胞胎）的重合度就是 run-to-run 噪音；兩個不同設定、同一重複序號之間的重合度就是差異（§3 Measures）。
  - **本地化指數**（localization index）＝雙胞胎平均重合度 − 不同設定之間的平均重合度；以引用網域的 Jaccard 計算，逐題計算後對問題平均，用 bootstrap 求 95% CI。0 表示地點的影響不超過噪音（§3 Measures）。注意：這個指數是**差值**，不是重合度本身；論文正文沒有給出雙胞胎重合度的絕對值。
  - 漂移對照：同一連線相隔三天；倫敦與悉尼相隔 30 分鐘測量（§4 RQ2）。
  - 安慰劑：計算引用了「另一個」研究地點的來源比例（§4 RQ3）。
  - 拆分查詢改寫和後端：只比較「兩次回答的搜索詞都沒寫地點」的配對（§4 RQ2）。
- 評估方式：
  - 客觀指標：是否搜索、搜索詞、引用 URL、搜索詞是否寫出地點（§3）。
  - 「本地來源」以規則判定：URL 中寫出回答所在城市或美國州名，或帶有該國網域後綴（§3）。只看 URL，不看頁面內容，可能低估本地來源。
  - 被推薦的商家、品牌、產品由語言模型抽取（排除目錄、評論站和政府機構）；人工抽查 36 個抽取結果中 29 個完全正確（約 81%）（§3）。
- 證據等級：**B**（真實商業引擎、每個設定重複兩次並以重複差作噪音基線、19 + 5 個地點、300 題）。限定：經 API 而非消費者介面、小模型為主、每個設定只有兩次重複、VPN 為資料中心 IP。

## 主要發現（逐條列出，附數字和出處節號）

**RQ1：地點改變本地型答案的來源**

1. ChatGPT 宣告地點（圖 1、§4 RQ1），網域本地化指數：
   - 「附近」型：兩個美國城市之間 0.14，不同國家城市之間 0.28；
   - 取決於地點型：0.17 與 0.43；
   - 非本地型：0.00 與 0.03，即來源不隨宣告地點變化。
2. Gemini 網路位置，不同國家之間：「附近」型 0.43（CI 0.40–0.46），取決於地點型 0.40；**非本地型仍有 0.23（CI 0.20–0.27）**（§4 RQ1）。也就是說，「最好的掃地機器人」這類與地點無關的問題，Gemini 換一個國家的網路也會換掉相當比例的來源。
3. 宣告地點也改變 ChatGPT 是否給出來源：沒有宣告地點時，它常改為反問郵遞區號；有宣告地點時 64–73% 的回答帶來源，沒有時是 46%（§4 RQ1）。
4. 主題差異（圖 2，ChatGPT 宣告地點、兩個美國城市之間）：取決於地點型問題中，公共服務最強（0.57，答案引用各州政府網站），電信／公用事業最弱（0.02，答案引用 FCC、全國電信商和比價站）。每個主題每組只有 10 題，作者自稱估計只是指示性的（§4 RQ1）。

**RQ2：兩個引擎走不同通道**

5. ChatGPT 忽略網路位置：不同國家網路之間，三組本地化指數為 0.00、0.01、0.01，都在噪音範圍內（§4 RQ2）。推薦商家也不隨網路變化（表 3：0.03、0.02、0.00）。
6. Gemini 忽略宣告座標（試點，見上），跟隨網路位置，**但只到國家層級**：紐約與洛杉磯之間指數 0.00（CI −0.03 至 0.04）；搜索詞寫出國家名的比例在「附近」型答案中是 56%，但**從不寫城市**（§4 RQ2）。
7. 漂移不能解釋國家效應：同一連線相隔三天，三組指數為 0.03、0.01、0.05；倫敦和悉尼相隔 30 分鐘測，差異與其他任何兩國一樣大（§4 RQ2）。
8. ChatGPT 宣告地點從兩條路進入：
   - 模型把地名寫進搜索詞：「附近」型搜索 100% 寫入，取決於地點型 48%，非本地型 0%（§4 RQ2、表 2）。表 1 例：「我附近的信用合作社」在博伊西被改寫成含「Boise Idaho」的搜索詞，在倫敦改寫成含「London England United Kingdom」。
   - 搜索後端自行本地化：兩次回答的搜索詞都**沒有**寫出地點時，來源仍有差異（指數 0.17，CI 0.09–0.25）；例如在博伊西的用戶問何時種番茄，ChatGPT 引用了俄勒岡州立大學的推廣服務頁面。兩邊搜索詞都寫出地點時，指數升到 0.37（§4 RQ2）。
9. ChatGPT 的本地化不隨距離衰減：「附近」型問題中，相距不到 1,000 公里的美國城市之間指數 0.13，相距超過 3,000 公里的是 0.14；與距離的 Spearman 相關 0.01；最近的一對城市相距 293 公里（§4 RQ2）。作者的總結：對 ChatGPT，每一個別的城市都是不同地方；對 Gemini，只有別的國家才是。
10. 預設地點（§4 The default location）：
    - ChatGPT 不宣告地點時，63% 的「附近」型問題以反問郵遞區號或城市作答（有宣告地點時是 4%）。它確實搜索時，搜索詞不寫州名；來源與美國城市條件的重合度 0.25，與其他國家只有 0.10；只有 11% 的「附近」型回答提到任何美國地名。作者據此判斷：預設是「未指明的美國用戶」，用全國性來源回答。
    - Gemini 的預設是網路所在的國家，不論宣告什麼地點。

**RQ3：本地來源與不同的商家**

11. 表 2（「本地來源」＝引用的 URL 寫出回答所在城市／州，或帶該國網域後綴）：

| 問題組 | ChatGPT 宣告：有搜索 | ChatGPT：搜索詞含地點 | ChatGPT：本地來源（美國） | ChatGPT：本地來源（他國） | Gemini：搜索詞含國家 |
|---|---|---|---|---|---|
| 附近 | 100% | 100% | 79% | 92% | 56% |
| 取決於地點 | 67% | 48% | 22% | 77% | 59% |
| 非本地 | 49% | 0% | 1% | 10% | 4% |

    安慰劑（引用寫出「另一個」研究地點的來源）低於 0.2%（§4 RQ3）。

12. 推薦的商家跟著來源一起換（表 3、§4 RQ3）：ChatGPT「附近」型回答平均點名 4.3 個商家／品牌／產品；兩次相同請求共享其中 23%，兩個不同宣告地點只共享 4%。
13. 表 3：推薦商家的本地化指數

| 比較 | 附近 | 取決於地點 | 非本地 |
|---|---|---|---|
| ChatGPT 宣告：兩個美國城市 | 0.18 | 0.14 | 0.01 |
| ChatGPT 宣告：兩個國家 | 0.22 | 0.22 | 0.03 |
| Gemini 網路：兩個國家 | 0.41 | 0.28 | 0.07 |

**對監測的含義（作者的定量分析，§4 Implications for monitoring、圖 3）**

14. 「附近」型問題：在一個美國城市宣告的請求，只推薦了另一個城市同一請求所推薦商家的 8%；同城重複則是 32%。15 個城市中被推薦的商家有 96% 只在一個城市出現。取決於地點型的差距小得多（31% 對 34%）。
15. 覆蓋率曲線（圖 3）：「附近」型問題，監測 1 個城市只能涵蓋 15 個城市全部被推薦商家的 9%，5 個城市 36%，10 個城市 69%，曲線不趨平。作為參照的非本地型：1 個城市 19%、5 個城市 53%，這部分差距來自重複請求之間的隨機變化。作者結論：監測需要重複請求，本地型問題還需要多個地點。

**Run-to-run 噪音**

16. 噪音以雙胞胎配對直接測量並從指數中扣除（§3）。正文給出的噪音量：推薦商家方面，兩次相同請求只共享 23% 的名字（「附近」型，§4 RQ3）；同城重複涵蓋 32%（§4 Implications）；非本地型問題中，單一城市只涵蓋 19% 的商家，完全來自重複間變化（§4 Implications）。網域層面的雙胞胎重合度絕對值，正文沒有報告。

**穩健性（§4 Robustness）**

17. 強制搜索臂（「Search the web:」）的指數與照原句問的臂相同：三組為 0.19、0.20、0.01（所有地點配對）。
18. 完整版 gpt-5.4（60 題 × 6 地點，720 個回答）本地化至少與小模型一樣強：0.26（CI 0.22–0.31）、0.35、0.11，對比小模型在同一批題目和地點上的 0.23、0.31、0.07；完整版在「附近」型搜索中也 100% 寫入地點。值得注意：這個子樣本中，**非本地型的指數是 0.11（大模型）與 0.07（小模型）**，不是接近 0；正文沒有給出這兩個數的 CI，也沒有討論。這與第 1 條「非本地型 0.00／0.03」的差異，可能來自子樣本包含跨國地點配對，但論文沒有說明。

## 對應原理和管線階段

- 原理編號：
  - [2] 查詢改寫：宣告地點透過模型改寫進入搜索詞（「附近」型 100%），而用戶原句沒有地名。這是「AI 搜的不是用戶打的那句話」的又一直接證據。
  - [3] 召回：地點經由兩個環節改變候選池——搜索詞改寫，以及搜索後端本身（搜索詞不含地點時指數仍有 0.17）。
  - [7] 可見度是隨機分佈、如何測量：用雙胞胎噪音基線把「地點效應」和「重複隨機性」分開；推薦商家的單次重合度只有 23%；本地型監測需要多地點。
- 管線階段：觸發（宣告地點改變是否給出來源，46% 對 64–73%）→ 檢索（查詢改寫、後端本地化）→ 生成／引用（引用來源與推薦商家）。
- 新原理候選：不是全新原理，但應作為原理 4.4 的**修正子項**——「地點有兩條通道：應用宣告的地點與網路推斷的地點；各引擎讀取的通道和粒度不同（本研究：ChatGPT API＝宣告、到城市；Gemini API＝網路、到國家）。對讀網路的引擎，連與地點無關的問題也會被本地化。」

## 對實踐的含義

（本節只記錄論文的研究含義，不寫操作策略。）

- 有實驗支持的結論：
  - 不控制地點的測量，量到的是一個未聲明的地點：ChatGPT API 不宣告地點時量的是「未指明的美國用戶」；Gemini API 量的是執行環境所在的國家（§4、§5）。
  - 兩個通道都要固定，比較才有效：只設地點參數，量到的是 ChatGPT 的該城市、Gemini 的運行所在國；兩者都不設，量到的是 ChatGPT 的美國泛用戶、Gemini 的本國（§5）。
  - 本地型問題的推薦商家幾乎不跨城市重疊（8%、96% 只出現在一個城市），單一城市的監測無法代表其他城市，即使是附近的城市（§4、§5）。
- 作者建議但未經驗證的推論：
  - 本地商家在 ChatGPT 中的可見度，取決於引擎針對地點化查詢找到的頁面（本地目錄、評論站、本地機構網站），而不是全國排名（§5）。這是從「搜索詞寫入地點＋引用寫出城市／州的來源」推出的，論文沒有直接測試哪類頁面。
  - 經 Gemini API 進行的任何研究都被執行網路所在國本地化，除非控制地點（§5）。這對解讀其他研究很重要，但論文沒有重新檢驗已發表的研究。
- 被證明無效或有害的做法：
  - 只從一個地點監測本地型問題的商家推薦（1 個城市只涵蓋 9%）。
  - 對 ChatGPT API 只換 VPN 出口：三組指數 0.00–0.01，等於沒有改變地點。
  - 對 Gemini API 只設宣告座標：試點顯示無效（無數字）。

## 局限與效度威脅

作者自述（§5 Limitations）：
- 使用 API 與小模型，不一定等同消費者應用；完整版模型的檢查只做了 ChatGPT。
- VPN 出口是資料中心 IP，只有 5 個網路位置；住宅連線下 Gemini 可能更細地本地化。
- 問題為英文、由作者自寫。
- 測量只描述 2026 年 10 月的引擎。

筆記者補充：
- 「Gemini 忽略宣告地點」只來自試點，正文沒有試點的樣本量和數字（§3 E2）。
- 「Gemini 不到城市層級」只靠一對美國城市（紐約對洛杉磯）（§4 RQ2）。
- 每個設定只重複兩次；雙胞胎重合度作為噪音基線本身也很嘈雜，而絕對重合度沒有報告，讀者無法判斷「0.43」相對於總體重合度有多大。
- 「本地來源」只看 URL 字串（城市、州名、國家網域），內容提到地點但 URL 沒寫的頁面會被漏算；美國的 .com 網站無法以網域後綴判斷國家，因此「美國 79%」與「他國 92%」用的規則不同，不宜直接比較。
- 推薦商家由語言模型抽取，36 個中只有 29 個完全正確，推薦商家的指數有測量誤差。
- Gemini 的國家效應中，查詢改寫和後端各佔多少沒有拆分。非本地型問題中 Gemini 搜索詞只有 4% 寫出國家，指數卻有 0.23，暗示大部分效應不經過搜索詞文字（筆記者推論，作者未檢驗）。
- 穩健性子樣本中非本地型指數 0.11／0.07，與主結果「非本地型不受影響」有張力，作者未討論。
- 只有英語國家，沒有改變查詢語言，因此無法與「語言閘門」的效應大小直接比較。
- 消費者 ChatGPT 介面是否把網路 IP 轉成宣告地點，本研究沒有測。

### 一、需加限定或改寫

1. **第04章_召回.md 第 167 行**（原理 4.4 因果鏈）：「出口 IP 則影響搜索後端把你當成哪個國家的用戶。」

2. **第04章_召回.md 第 174 行**：「**語言決定候選集合被整體換成『本地型』，出口 IP 決定是哪個國家的本地。**」

### 四、總判斷

**需要更新，屬中等程度的修訂**，集中在第 4 章原理 4.4、爭議 3.3、要點 7、第 13 章 B4，並連帶第 0、9、12 章的相關句子。

理由：
- 教材現行說法「IP 選國家、城市要寫進句子、地點設定主要影響排序」建立在一項服務商小樣本研究（消費者網頁介面）和一個只測 Gemini／AIO 的從業者案例上。本文是第一項在同一設計中分開操縱宣告地點和網路位置的研究，B 級，學術作者，有噪音基線、漂移對照和安慰劑。
- 它沒有推翻「地點／市場是閘門」這個大方向，反而加強了它（地點會換掉大部分來源和推薦商家）；但它把「出口 IP」這個單一機制拆成「兩條通道、依引擎不同、粒度不同」，並推翻了「城市層級必須由用戶把地名寫進句子」作為通則（ChatGPT API 會自己寫入，後端也會自行本地化）。
- 限制要同時寫進教材：只測了 API 與小模型（完整版只驗證 ChatGPT），VPN 是資料中心 IP，Gemini 的「忽略宣告地點」只是試點、「不到城市」只有一對城市，只有英語，時間是 2026 年 10 月。因此修訂時應寫成「在 API 上觀察到」，並保留消費者介面可能不同的提醒，而不是把引擎差異寫成定律。
